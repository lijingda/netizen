## 范围

自主模式是默认不启用的实验能力。只有普通群主线／群话题内显式选择自主模式的 Binding，
才把真人未 @ 候选交给外部决策服务。显式 @ 和控制操作保留原路径，选中输入仍由现有 Runtime start/steer。
不做自动 catch-up、消息队列、插件系统、Laya 自动部署或第二个 Codex／Channel／数据库。

决策上下文仅保存真正被接收的选中消息、显式 @ 消息、实际最终正文和摘要；不保存跳过正文。
摘要是同一 AsyncCodex 的独立 ephemeral Thread 文本任务，不 fork 用户完整历史。
判定不可用不自动消费、不逐条通知；Admin／`/status` 提供状态。所有远端事实需按实际部署版本重新验证。

## 可移除边界

- 决策协议、配置、上下文、预算、摘要集中在 `netizen/autonomy/`，不让原生执行依赖提供方。
- 自主开关与上下文归专属 SQLite 表，复用现有 Store 连接与事务，不扩展 `MentionContextMode` 或定时计划 JSON。
- 输入选择、实际接收、最终结果和会话删除是有限的接入点；Admin 与会话卡片只展示各自职责内的配置。
- 明确停用后，迟到的自主判断不得启动新执行；已接收的普通 Turn 不受干扰。
- 未来正式移除时，将原自主会话解释为普通 @／current-only，保留 Binding、原生历史及工作成果。
  只清理实验配置、专属数据与接入点；不要用旧整库快照覆盖实验期间的正常数据。

## 实现接入清单

| 边界 | 位置与职责 |
| --- | --- |
| 可移除核心 | `netizen/autonomy/`：提供方协议、私有配置、上下文、消费决策、摘要与清理 |
| 唯一持久化 | `BindingStore.autonomy`：同连接／事务，三张 `autonomy_` 表，Binding 删除级联 |
| 输入／结果 | `channel_app.py`：未 @ 候选、实际接受后的记账、确认最终正文；不接入 Files／Activity／固定提醒 |
| 原生准入 | `CodexRuntime.submit(input_guard=...)`：可选同步校验，无提供方类型；原有 start／steer 未替换 |
| 装配 | `Settings`／`ServiceCore`：同一 AsyncCodex，接收候选，先关自主准入再清理临时资源 |
| 产品入口 | Admin 独立 JS／API；`/new`、`/config` 只选择模式；指南与安装成功提示 |

私有配置由配置 YAML 所在目录派生为 `credentials/decision-model.json`，正常实例在
`~/.netizen/credentials/decision-model.json`。Admin 原子保存并更新进程，不监听文件变更。
该文件必须由当前账号所有、无其他用户权限；密钥不回显。缺少或损坏它不妨碍基础服务启动。
本分支没有写入任何实际服务凭据，也没有部署模型。

## 实验限制和再次启用前检查

- Jev／Laya 兼容的是协议，不承诺相同判断质量。需要单独测试中文噪声、跟进、省略上下文、
  延迟、成本和误触发容忍度；Laya 小窗口尤其容易放不下上下文。
- 输入预算采用保守 UTF-8 字节估算，不是模型 tokenizer 的精确计数。超限不截断当前消息。
- 摘要每次只处理不超过 64 KiB 的完整旧记录前缀；剩余原文保留，后续新候选可继续压缩。
  单条已接受记录过大时不截断或隐式丢弃，自主判断可能保持不可用；显式 @ 仍可用。
  临时摘要失败有 30 秒冷却，恢复只影响新候选，不补跑旧消息。
- 未 @ 自动消费时，只有可准确计数才附加 gap 提示；显式 @ 保持原有输入结构但会记入决策上下文。
  重启、模式变更或无法确认连续接收时不伪造条数。计数只涵盖符合候选条件的真人普通消息，不含控制命令／机器人。
- 临时摘要 Thread 使用公开 read-only sandbox 与 deny-all approval，不改用户 Thread；
  这不是“无工具／无网络”的完整隔离。其真实生命周期与原生工具环境需另行验证。
- 撤销校验截止原生输入 RPC 发起之前。已经发起、但尚未收到回包的请求不能安全当作未执行或自动重试。
- `make check` 是合成／本机兼容性门禁，不等于真实飞书未 @ 投递、外部模型效果或原生摘要验收。
