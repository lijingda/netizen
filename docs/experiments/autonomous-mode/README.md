## 范围

自主模式是默认不启用的实验能力。只有普通群主线／群话题内显式选择自主模式的 Binding，
才把真人未 @ 候选交给外部决策服务。显式 @ 和控制操作保留原路径，选中输入仍由现有 Runtime start/steer。
不做自动 catch-up、消息队列、插件系统、Laya 自动部署或第二个 Codex／Channel／数据库。

决策上下文仅保存真正被接收的选中消息、显式 @ 消息、实际最终正文和摘要；不保存跳过正文。
摘要是同一 AsyncCodex 的独立 ephemeral Thread 文本任务，不 fork 用户完整历史。
判定不可用不自动消费、不逐条通知；Admin／`/status` 提供状态。所有远端事实需按实际部署版本重新验证。

## 可移除边界

- 决策协议、配置、上下文、预算、摘要集中在 `netizen/autonomy/`，不让原生执行依赖提供方。
- 自主开关与上下文归专属 SQLite 表，复用现有 Store 连接与事务，不扩展 `MentionContextMode` 或定时计划 JSON。
- 输入选择、实际接收、最终结果和会话删除是有限的接入点；Admin 与会话卡片只展示各自职责内的配置。
- 明确停用后，迟到的自主判断不得启动新执行；已接收的普通 Turn 不受干扰。
- 未来正式移除时，将原自主会话解释为普通 @／current-only，保留 Binding、原生历史及工作成果。
  只清理实验配置、专属数据与接入点；不要用旧整库快照覆盖实验期间的正常数据。

## 合并与退出注意事项

长期分支不能保证没有冲突。重新合并前须复核 main 的 Channel 接收门禁、消息准入、卡片 callback、
共享原生问题输入、最终结果展示及数据库 schema。重点比较真实行为，不能只解决文本冲突。

实验 schema 的升级／移除遵循当前只接受精确版本的策略：新增专属表不等于旧二进制自动兼容。
不得为了实验而跳过 schema 校验、静默迁移生产库或扩大原生 SDK 的私有适配面。
提交中的研究文件是截至记录日的证据，不是更新 SDK／供应方后仍然成立的运行保证。
