# 以飞书展示 Turn 统一各后端的回复展示

## 背景

同一条输入可能对应多个原生物理 Turn，两个后端对此采用了两种展示模型。

- **Codex Goal：** 自动续跑按 [ADR 0084](0084-separate-goal-controls-from-logical-turn-replies.md) 共用一条任务回复链。阶段性答案跨物理 Turn 累计，Activity 每轮重置，中间 Turn 不展示 Result/Files。
- **Claude 后台唤醒：** 按 [ADR 0105](0105-extend-backends-through-capabilities-and-shared-presentation.md) 阶段 C 的实现，每个有正文的物理 Turn 单独回复，状态行在新旧卡之间交接。

两种模型使展示层需要理解 Goal、逻辑 Turn、唤醒和后端。回复呈现器允许一个逻辑会话接受任意物理 ID，Goal 有单独的快照读取与留存规则，Claude 有专用的物理回答、状态行和逻辑终态路径。今后接入飞书 COT 消息、其他 Agent 或 Claude 的自动续跑时，每种展示调整都要在多处分别实现。

维护者要求统一展示概念。每个物理 Turn 映射为一个飞书展示单位，各 Agent 只负责映射，展示样式只针对这个单位设计。长 Goal 产生较多卡片是可以接受的代价。

以下事实来自对 `main@71feb18` 的只读调查，记录在本地研究目录 `docs/research/multi-agent-positioning/phase5/` 的 `PRESENTATION-TURN-FACTS.md` 中。

- **Codex Goal 的唯一 Tap 能看到每个物理 Turn 的事实。** 这些事实包括原始 `turn/started`、各 Turn 已完成的 `agentMessage` 及其 phase、终态 status、成功的 `fileChange`、生成的图片，以及匹配的 diff。SDK 的逻辑游标会丢弃后续 start，并改写条目的 Turn ID，因此这些事实只能在 Tap 处、换轮重置之前冻结。现有 Tap 向 Activity 投影 Activity、结构化问题和稳定的阶段性答案；另外，它为最终物理 Turn 保留最新的 diff，用于发现文件。
- **中间 Turn 的子任务文件无法完整证明。** 若 P1 的子任务在 P2 开始前尚未完成根核对，现有收集器会丢弃这部分证据，以免把 P2 派给同一子任务的工作算进 P1。P1 自身已证实的直接文件仍可使用。
- **Tap 快照不等于最终历史。** 最终答案或文件可能只在四项终态证据的历史读取中出现。
- **Claude 的匿名唤醒和 cron Turn 要到 Result 才能确定归属。** 无正文、无片段的匿名成功 Result 不产生新的回复内容。
- **固定版 SDK 在自动续跑被中断时可能结束逻辑迭代器。** 之后的物理 Turn 不再到达 Tap，现有的 unknown 通知继续作为恢复手段。

## 决定

### 1. 展示 Turn 按物理 Turn 身份界定

- **身份：** 一个展示 Turn 由精确所有者（Binding 或 Side）、原生会话和物理 Turn 身份确定。
- **内容：** 只承载该物理 Turn 的 Activity、阶段性答案、结果和本轮文件。阶段性答案只追加到所属展示 Turn。
- **形态：** 沿用现有传输规则，决定使用回复卡、富文本、Result 加 Files 卡，还是独立的阶段性答案消息。这些选择本决定不改变。以后接入的 COT 消息是同一单位的另一种传输形态。
- **何时没有可见消息：** 是否产生可见消息按现有投递规则判断，包括空 Codex 结果的兜底文本、结果静默、只有阶段性答案，以及关闭已有卡片。既无正文也无阶段性答案的匿名成功 Turn 不新发回复内容。

### 2. 逻辑运行只承载生命周期信号

- **界定：** 一个逻辑运行由一次被准入的执行启动界定，包括人工输入、定时输入、会话协作工具启动的普通执行、`/goal` 启动，以及流结束后的 resume。它保留启动时的 Completion Origin 和任务发起人。
- **沿用当前运行，不新开：** steer、原生 join 和同流 resume 都沿用当前逻辑运行，不改变发起人。
- **职责：**
  - 原消息上的生命周期表情；
  - 最新一张已确认、带状态的卡片上的状态行；
  - 停止后对提醒的抑制；
  - 结束提及；
  - 定时新话题首轮的完成回执。
- **不承载正文。**

### 3. 现有规则限定在展示 Turn 内保留

| 规则 | 保留方式 |
| --- | --- |
| 投递与降级 | 各路径现有策略不变，只是作用于单个展示 Turn：Codex/Side 在终态卡更新结果未知后，允许一次有界的富文本兜底；定时新话题首轮不发布第二份结果；Claude 按本轮投递账本，对未确认的内容提示一次。投递位置核验发现矛盾后，停用记录仍以 Binding 为范围，并延续到之后的 Turn。 |
| 结果静默 | 物理 Turn 正常完成、自己的 `suppress_reply()` 标记仍然有效且原始 final 为空时，省略该 Turn 的 Result、正文图片和 Files，即使已有文件证据。这一判断在准备 Files 和图片之前进行。阶段性答案、生命周期反馈和新输入撤销规则不变。下一个物理 Turn 默认不静默。 |
| 结束提及 | 沿用 [ADR 0063](0063-mention-task-initiators-in-terminal-results.md) 的提醒路径和资格判定，范围是整个逻辑运行，最多尝试一次。如果现有路径在发送时就能携带提及，而且此时已符合条件，就内联提及。否则单独提醒，引用本运行最新一条已确认的回复或卡片；例如 Claude 的正文在逻辑结束之前发出时，就属于这种情况。以下两种情况保留现有例外，引用原输入消息：整个运行没有内容回执但符合条件；无卡片的显式静默结束，即使已经发出阶段性答案。只有失败投递的运行不提醒；显式停止会抑制提醒。 |
| 问题卡 | 独立的问题卡路径保留在唯一观察链上，按物理 Turn 和条目去重。回答仍按原 Binding 或 Side 当时的状态准入。 |
| 定时任务 | 定时新话题首轮的投递回执由逻辑结束时已接受的最终投递和阶段性答案回执汇总一次。阶段性答案或之后的 Turn 都不能把它标记为已发送，也不能触发自动归档。Agent 自评仍由已核实的当前物理 Turn 通过工具显式写入（[ADR 0102](0102-record-agent-self-assessment-for-scheduled-topic-runs.md)）。 |
| Side | Side 的身份、反馈、Files 路径和 `handle.run()` 终态权威都不变。 |
| Files 分页 | 已发出卡片的清单继续按既有格式解码；新清单记录物理 Turn 来源。 |

### 4. 标题与摘要使用同一条展示层规则

- **规则的输入：** 卡片标题、折叠摘要和 Files 分页重绘都取两个输入：物理 Turn 的终态，以及可选的、已核实的逻辑运行结果。
- **本轮完成与整体完成分开显示：** 一个已完成的物理 Turn，如果它所属的运行仍在继续，就显示本轮完成。只有运行结果已核实为成功时，最新的展示 Turn 才显示整个任务已完成。
- **不变的部分：** 单轮普通任务的输出保持不变。
- **有意改变的部分：** Claude 首答在仍有后台工作时，目前会显示"任务已完成"。这一点会改变，并在第一个实施 PR 中完成。

### 5. 展示层只消费类型化事件

- **事件集：** 展示层不按后端、Goal、唤醒或 cron 分支，只接收以下事件：
  - `TurnOpened`：展示 Turn 身份、可选的逻辑运行、已核实的投递目标、冻结的任务反馈；
  - `ActivityChanged` 与 `PartialAnswer`；
  - `TurnResult`：终态、正文、安全错误、本轮文件和剩余片段；
  - `RunState` 与 `RunEnded`。
- **Goal Tap 的投影范围扩大：** 修订 [ADR 0052](0052-project-safe-turn-activity-with-one-consumer.md) 的允许清单。Goal Tap 在换轮重置前，除了 Activity、结构化问题和稳定的阶段性答案，还投影本轮最终文本、终态和直接文件证据。
- **原始通知照常交回：** 即使投影失败，Tap 也原样返回原始通知。
- **消费链约束不变：** 每条原生事件流仍只有一个消费者，飞书 I/O 不进入原生消费链。

### 6. 各后端只做映射

**Codex 普通 Turn 与 Side** 一一映射，输出保持不变。

**Codex Goal** 的每个已观测物理 Turn 映射为一个展示 Turn：

- **结果写入时机：** 已完成的物理 Turn 先作为候选保留。下一次 start 证明它是中间 Turn 时，用 Tap 冻结的事实一次性写入结果。若四项终态证据确认它是最终 Turn，最终历史读取先补齐候选中缺失的答案和文件，再一次性投递。
- **观察中断：** 如果 Goal 转入观察不可用，未定的候选会在有界的 unknown handoff 内退役。观察不可用包括迭代器关闭后，最终读取失败、超时或与历史不一致。这种按时限进行的 handoff 只释放展示候选。保留执行隔离，发出现有的观察通知。已发布的展示 Turn 不受影响。
- **控制回执未知：** 若最终证据已核实，而 clear 或 steer 的控制回执结果未知，答案和控制通知都保留。
- **暂停与恢复：** 暂停和同流 resume 保留当前运行、当前展示 Turn 和发起消息。流结束后的 resume 从它第一个被观测到的物理 start 起，在 resume 消息上开启新的运行。
- **中断：** 物理 Turn 的终态如实显示，此前的阶段性答案保留，被中断的 Turn 没有 Files。显式停止抑制提醒。
- **文件：** 每个成功的物理 Turn 只统计本轮已观测的直接文件和成功 patch，不跨 Turn 聚合。子任务统计只在最终 Turn 上取得；子任务证据不完整时，总计记为未知。
- **保持不变的契约：** 四项证据约束逻辑收尾；本进程已确认的显式 clear 仍然有效；只对 completed 自动收尾；独立的管理卡不变。非 unknown 槽位要等最终物理 Turn 的 Result/Files 在现有时限内完成 handoff 后才释放。

**Claude** 的首答、每次唤醒和每个 cron Turn 各映射为一个展示 Turn：

- **匿名 Turn：** 在 Result 确认归属后才打开。
- **无人工归属的 Turn：** 发往已核实的会话位置，没有提醒对象。
- **纯文本模式：** 只有在发送时，所属输入仍有至少一个后台任务，正文末尾才附上任务数。正常发送和兜底发送都按这条规则。

### 7. 不恢复进行中的展示

服务重启后，不恢复进行中的展示。

## 实施与验收

分两个 PR 交付。

**重构展示层**

- **改动范围：** 展示层改为只消费上述事件。Claude 的专用物理回答、跨卡状态交接和逻辑终态路径并入通用路径，并完成第 4 条中 Claude 标题的有意调整。
- **Goal 的过渡映射：** Goal 暂时把所有物理 Turn 映射到同一个展示 Turn，复现现有的单卡行为。阶段性答案去重和 Files 回调仍使用原始物理 ID。
- **验收：**
  - Codex 普通 Turn 的差分夹具逐字节不变；
  - 普通 Turn 与 Side 的同卡、兜底和 Files 行为测试保持通过。

**切换 Goal 的映射**

- **改动范围：** 只修改 Goal 映射。同步修改 design.md 和 deployment.md 中受影响的验收条目，并有意更新相关的 Goal 测试。
- **验收：**
  - 用真实 bundled App Server 跑一个至少两个物理 Turn 的 Goal，核对两个展示 Turn 各自的答案、文件和终态，以及唯一一次符合条件的提醒；
  - 飞书展示另行验收。

每个 PR 的规格先写明阻断标准，以下情况阻断合并：

- 内容送到错误的展示 Turn、会话或人；
- 提醒发错对象，或者重复、缺失；
- Netizen 逻辑造成内容丢失；
- 缺失本应发出的降级提示；
- 悬挂、泄漏或异常逃逸；
- Codex 普通 Turn 或 Side 的行为变化。

失败路径里的观感问题，以及已被通用规则覆盖的注入异常变体，不阻断合并。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 一个逻辑运行共用一张卡，Claude 向 Goal 现有模型对齐 | 不采用。展示层仍要理解逻辑运行和换轮；数小时后才到的唤醒结果会静默更新旧卡；COT 和其他 Agent 也没有统一的单位。 |
| 各后端各自实现展示 | 不采用。重复实现会让样式分化，这正是本决定要消除的状态。 |
| Goal 物理 Turn 完成后立即发布结果，再用四项证据对账 | 不采用。需要对已发布的卡片和回执补写或去重。保留候选只需等到下一次 start 或最终读取，每个展示 Turn 的结果只写一次。 |
| 为每个物理 Turn 强制生成可见消息 | 不采用。无内容的匿名唤醒会产生空卡，并改变 ADR 0105 中无正文回执的行为。 |

## 后果

- **卡片数量：** 一个长 Goal 产生的任务展示数量与物理 Turn 数相同，另加一张管理卡。若以后要把同一逻辑运行合并为一条消息，或把它做成可选配置，需要另行决定，不在本契约之内；这种调整不需要修改 Agent 映射。
- **飞书限额：** 每条新消息单独计入飞书的发送频率，每张新卡有各自 14 天的更新窗口。快速换轮会更早接近同一聊天每秒 5 条的回复上限。
- **AGENTS.md：** Goal 条款改为："保留 Goal 的四项证据逻辑收尾与有界最终 handoff，包括当前 Turn 完成期间已确认的显式 clear；每个展示的阶段性答案、Result 与 Files 绑定其精确物理 Turn。"
- **design.md：** Goal、阶段性答案和本轮文件章节随实施 PR 同步修改。
- **术语：** 第一个实施 PR 在 `CONTEXT.md` 中加入"展示 Turn"和"逻辑运行"；第二个实施 PR 更新"本轮文件"与"阶段性答案"的定义。
- **本决定修订：**
  - [ADR 0052](0052-project-safe-turn-activity-with-one-consumer.md)：Goal 共用一张卡、中间 Turn 无 Result/Files，以及 Tap 的投影允许清单；
  - [ADR 0053](0053-show-exact-turn-line-statistics-in-files.md)：只取最终 Turn 的路径快照；
  - [ADR 0056](0056-count-successful-patches-in-task-files.md)：可统计的 Turn 范围扩大到每个成功的物理 Turn，仍不跨 Turn 聚合；
  - [ADR 0079](0079-deliver-partial-answers-with-existing-reply-presentation.md)：阶段性答案跨换轮累计，以及只取最终 Turn 的 Result/Files；
  - [ADR 0084](0084-separate-goal-controls-from-logical-turn-replies.md)：不为每个物理 Turn 单独发卡、阶段性答案在逻辑执行中累计，以及只取最终 Turn 的 Result/Files。
