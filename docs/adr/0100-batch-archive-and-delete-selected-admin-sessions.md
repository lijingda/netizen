# Admin 普通会话按当前页勾选批量归档与删除

## 背景

会话随使用持续累积。Admin 普通会话列表只能逐行归档或删除，每个删除各自确认；Project
删除（ADR 0060）和 worktree 级联删除只能清理整个 Project 或 worktree，无法处理“保留
Project，整理其中三个月没动过的几十个会话”这类常见需求。

ADR 0031 的操作矩阵把“多个对象的批量 native mutation”列为不提供：“筛选和多选不能转换为
批量 archive、stop、close 或 delete；每个未知副作用必须独立停住。”ADR 0054 与 0060 重申了
这条边界。它防的是两件事：按任意筛选结果对管理员没有逐条看过的会话执行变更；某一项结果
未知时被后续执行淹没或自动续跑。

现有单项接口已经能把结果分清：

- 每行的归档、删除都有自己的一次性 exact action grant；
- 409 证明这一项没有完成：授权过期或已消费、状态已变化、归档对账确认仍在 active 目录、
  删除收到原生明确拒绝（ADR 0094）；404 表示目标已不存在。两者都只关乎这一个会话；
- 结果无法确认时返回 503 `state_unknown`：对账失败或超时、调用断开、原生已成功但本地
  提交失败。未知状态只留在该 Binding（ADR 0037/0049），不关闭其他会话的准入。

因此可以在守住上述两点的前提下开放显式勾选的批量操作。

## 决定

### 范围

只在 Admin 普通会话列表提供，只作用于当前页显式勾选的行（每页最多 100 条）。不提供
“按筛选条件全部执行”或跨页勾选；勾选随页面身份（已应用查询、排序、每页条数和 cursor）
存在，换页、改筛选或排序、切换会话状态或离开页面即清空。同一页重新读取时只保留仍在页上的
勾选。

会话状态筛选是单选，每页同质：

| 会话状态 | 批量操作 | 每项调用 |
| --- | --- | --- |
| 未归档 | 归档、删除 | `sessions/archive`、`sessions/delete-materialized` |
| 已归档 | 删除 | `sessions/delete-materialized` |
| 未开始 | 删除 | `sessions/delete-lazy` |

临时会话、飞书 `/sessions` 卡片，以及恢复、停止、释放订阅、Side 结束不提供批量入口。

### 先刷新，再确认

列表不再自动刷新；行授权在列表读取时签发、10 分钟后失效，归档和删除授权也不绑定运行态。
在旧页面上直接批量执行会中途遇到授权过期，或把页面加载后才开始运行的会话一起归档、删除。
因此点击批量操作后，先按同一页面身份重新读取当前页，按 Binding ID 重新匹配勾选，用新行和新
授权生成确认清单。读取失败则不执行任何一项。

确认弹窗逐条列出每个将执行的会话（名称、Netizen 会话编号、Project、聊天），包括折叠分组中
被隐藏的已选行，并标出当前会话和正在运行或状态未确认的会话：归档与删除不等待空闲，App Server 会关闭正在
运行的任务（ADR 0049）。已移出本页或已不支持该操作的勾选项单独计数，不执行。删除沿用单项
删除的永久后果说明和危险样式。

### 执行与停止

浏览器按页面顺序逐项调用上表的既有单项接口，每项消费该行的 exact grant，一次只执行一项。
不新增服务端批量路由、授权类型、清单 fingerprint、持久队列或后台续跑；服务端看到的是一串
与单行操作完全相同的请求，各自记录既有 `admin_mutation` 日志。

- 成功：记为完成，继续下一项；
- 409 或 404：记为未完成并显示服务端原因，继续下一项；
- 其他任何结果（503、504、500、400、403、429、网络错误、无法解析的响应）：该项记为结果
  未确认，立即停止，剩余项记为未执行；
- 登录过期：停止，按既有登录过期处理关闭弹窗，提示已完成数量并要求重新登录后刷新核对；
- 管理员可随时停止剩余项。已发出的请求在服务端继续完成（HTTP 断开不撤销 mutation），浏览器
  不再等待它，将其记为结果未确认。

任何一项都不自动重试。结束后只刷新一次列表，汇总完成、未完成、结果未确认和未执行，逐项
保留原因。关闭页面等同于停止：在途项在服务端完成，其余不执行，重新打开不续跑。

## 被拒绝的方案

- **按筛选结果全部执行或跨页全选。** 管理员没有逐条看过目标；cursor 分页没有总数，稀疏页
  可能为空，无法给出准确清单。这仍是 ADR 0031/0060 的边界。
- **服务端批量接口（清单授权加服务端循环）。** Project 删除需要服务端循环，是因为全部对象
  完成后要提交 Project 墓碑，并在过程中持有进程内 intent；会话批量没有聚合状态需要提交。
  服务端循环只会多出一套授权、预算和部分结果模型，而浏览器逐项调用让每一项与单行操作走
  同一路由、同一授权、同一日志。
- **遇到第一个失败就停（与 Project 删除一致）。** 409/404 已证明该项没有完成，且只关乎这一
  个会话。批量清理中常见的分支来源被拒删（ADR 0078）、并发修改不应阻断其余互不相关的
  会话。
- **并发执行。** 增加 App Server 负担，结果顺序难读；常见规模下顺序执行已足够。
- **自动归档策略（N 天未更新自动归档）。** 等于新增调度与策略层。
- **飞书卡片批量。** 受卡片容量与回调载荷限制，且不保存 card session；Scope 参与者也不应获得
  跨会话批量删除能力。

## 后果

- 一次确认最多可永久删除 100 个会话，误操作的影响范围变大；确认清单逐条列出目标，删除
  使用危险样式。管理员凭据泄露的损失半径不变，逐个调用单项接口本来就能做到。
- 批量执行期间不续期授权。执行时间超过授权有效期时，剩余项会以授权过期记为未完成，需要
  刷新后重新勾选。
- 删除仍有持久分支引用的来源会被原生拒绝，在批量清理中会较常见；结果按项列出原因，可在
  分支处理后重试。
- ADR 0031 中“批量 mutation 在 Admin HTTP route/controller 不可达”的门禁仍然成立：本决定
  不新增服务端路由。不触及 SDK Adapter 与原生生命周期，不触发 live probe；Admin 真实
  浏览器操作需人工验收。
