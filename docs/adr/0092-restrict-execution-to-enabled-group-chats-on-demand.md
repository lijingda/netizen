# 按需限制机器人只在已启用的群聊中执行

谁能把机器人拉进群，谁就让该群全部成员获得服务账号的 Codex 工具与文件访问能力；群成员
由群主决定，部署者无法控制。此前准入只由飞书应用可用范围和群成员关系决定，ADR 0080 也
明确不引入 Channel 准入规则。现在增加一个实例级群聊准入开关：管理员需要时可切换为“仅已
启用的群聊”，此后机器人只在名单中的群执行。单聊和单聊话题不受影响，仍由应用可用范围决定。

新实例与升级实例都默认“全部群聊”。Netizen 的信任边界仍是受信用户与应用可用范围；默认值
不改变任何现有行为，也不给首次使用增加步骤。代价是只有了解风险的管理员才会开启，因此
Admin 必须醒目显示当前模式及其风险，切换时明确提示其他群会被挡住；启用一个群也要足够直接：
实例管理员在该群发送 `/enable` 即可，不必去 Admin 查找 chat ID。

## 规则

- 配置位于实例 YAML 顶层 `groupAccess`：`mode: all | only` 与 `chatIds`（精确 chat ID，
  去重后最多 1000 个）。`all` 下保留 `chatIds` 但不生效，来回切换不丢名单。一个群聊 ID
  同时覆盖其主线和全部话题。
- `only` 只看 chat ID 是否在名单中，聊天类型仅用于豁免单聊；类型为话题、未知或缺失都不妨碍
  名单命中。只在需要确认单聊豁免时查询聊天类型；`all` 不增加任何查询，也不新增缓存或持久状态。
- 编辑沿用 `sessionTools` 的机制（ADR 0081）：实例管理员、同源请求与一次性 action grant；
  配置快照冲突检测、原子写入，成功后替换进程内规则；外部修改配置时拒绝覆盖。不新增文件、
  数据库表、权限服务或角色。
- 实例管理员在群里发送 `/enable`（群中照常需要 @机器人）即把该群加入名单。这是未启用的群中
  唯一会处理的命令：在准入检查处只识别这条命令文本，不做输入准备、不创建会话、不提交给 Codex。
  发送者须是本实例的管理员（ADR 0080 的飞书身份，按应用与 open_id 精确匹配）；其他人只收到
  “只有实例管理员可以启用本群”，管理员名单不可读时不启用。`all` 下同样加入名单，并说明切换为
  限制模式后生效；单聊中说明无需启用。写入沿用上一条的配置编辑与冲突检测。
- 每条入站在最早的入口捕获当前规则并只检查一次。不在名单中的群里，消息和卡片动作都不做
  输入准备（不读取引用、补充历史、图片或附件），不创建会话，也不提交给 Codex。这同样适用
  于除 `/enable` 外的命令、Side 话题、提问卡回答以及会话卡片上的停止、归档等按钮；这些群改由
  Admin Web 管理。
- 修改规则不撤销已接受的输入，不中断运行中的任务，结果照常投递。已有会话、Side 和定时
  计划都保留，只是该群之后的输入不再执行。运行中的任务若提出问题，群内无法作答，需在
  Admin 停止它或重新启用该群。
- 定时任务在投递时检查目标群：新话题计划与原会话计划指向未启用的群时，本次执行以明确的
  错误码失败，不修改计划，也不自动暂停（与 ADR 0061、0070 已有的执行失败语义一致）。
  原会话计划仍先捕获准入、再查询聊天类型，拒绝发生在发布锚点和准备输入之前；聊天验证失败
  沿用原有错误，不误报为群未启用。
- 会话协作工具的 create 与 send 指向未启用的群时拒绝；聊天验证失败仍返回原有错误。read、
  wait 和发现仍只受 `sessionTools` 范围约束，因为它们不在该群执行。
- 在未启用的群中，对触发消息和卡片动作尽力回复一条说明：本群未启用，消息不会执行，请实例
  管理员在本群发送 /enable 或在 Admin 中启用。消息保留原有 @ 触发条件；提示不去重、不持久化，发送失败只记录日志，不重试，
  也不改投聊天主线。卡片不在名单中且无法确认是单聊时同样拒绝（fail closed），卡片保留原样；
  Channel SDK 会对同一人重复点击同一按钮去重，这类点击不再回复，群重新启用后应重发命令取得新卡片。

## Admin

- “系统管理”中醒目显示当前模式；为“全部群聊”时附一句风险说明：群成员共享服务账号的工具与
  文件权限，可按需限制为已启用的群聊。
- 名单用现有的群聊选择器维护，显示群名与 chat ID。
- 从“全部群聊”切换到“仅已启用的群聊”时，确认框写明保存后只有名单中的群可以执行、其他群的
  新输入不会执行，并提示管理员可在群里发送 `/enable`。不自动预填已有会话所在的群：管理员可以
  先在各群发送 `/enable` 再切换，漏掉的群会收到提示，随时可以补启用。

## 不做的事

不对单聊或个人设限，不引入角色、Project ACL 或按会话创建者区分的权限。本次不订阅
`bot_added` 入群事件：入群时主动提醒需要新的事件订阅与开通权限（ADR 0035），留作后续。
准入只决定 Netizen 是否在该群执行，不改变 Codex 原生工具、sandbox 或审批策略。
管理员身份在飞书中只额外用于 `/enable`，不扩展为其他命令的权限；不提供 `/disable`，移除群和
切换模式仍在 Admin 中进行。

## 验证

- 规则解析、名单上限与配置快照冲突的单元测试；`all` 与 `only` 下群主线、群话题、单聊的
  入站矩阵。
- 未启用的群中，消息、命令与卡片动作都不进入输入准备和 Runtime，触发时回复说明；定时输入被
  拒绝时不发布锚点、不准备输入、不提交执行。
- 修改规则不影响已接受的输入和运行中的任务；定时投递与协作 create/send 的拒绝路径和错误码。
- `/enable`：管理员与非管理员、`all` 与 `only`、单聊、管理员名单不可读、配置冲突；未启用的群中
  处理 `/enable` 不进入输入准备和 Runtime。
- 真实飞书验收：一个已启用群和一个未启用群，各验证一次消息、卡片动作与定时投递；在未启用群中由
  管理员发送 `/enable` 后新消息可以执行。
