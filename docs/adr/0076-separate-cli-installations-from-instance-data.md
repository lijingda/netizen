# 用普通 Python CLI 分发程序，以实例启动负责数据准入

用户明确选择常规 Python 包：发行名 `netizen-cli`、模块 `netizen_cli`、命令 `netizen`。
使用用户选择的 Python 环境，不捆绑解释器，不在每个 root 保存程序／venv／release。
每个 `.netizen` 只拥有该实例的配置、凭据、数据库与日志；环境之间可以安装不同版本。
系统服务固定解释器与 root，不随终端 PATH 改变。内置 Skills 从实际安装包加载，仍注册
到同一个 App Server，不写全局 Skills，不新建实例私有 Codex 状态。

显式 setup 初始化新实例；每次实际启动都在 lifetime lock 内校验与按需迁移，再进入
只接受当前完整 schema 的 Runtime。缺失数据库不能冒充首次初始化。SQL 迁移保持单
事务，提交前失败回滚；提交后启动失败保留新库，不自动降级或恢复旧快照。这替代
ADR 0075 的安装期迁移和 release/database 跨操作回滚，保留 v14 基线及冻结迁移规则。

`netizen update` 是当前安装环境的一次性维护操作，不接受 --root。系统服务定义作为
受管实例清单，不新增注册表。先确认安装归属与服务状态，记录运行集合，停止且确认退出，
再由替换范围外的最小协调器调用用户包工具、新进程验证、恢复原运行集合并分别报告。
pip／uv pip 的可靠无变化预检查可以跳过停启；uv tool 接受无变化也可能重启一次。
安装归属使用原生接口优先的有限布局适配，歧义或不支持在停服前拒绝，不解析安装日志、
试升级探测或自动换工具。停服失败直接中止，不补偿已停实例；环境状态不明不盲目启动；
部分启动失败不跨实例回滚。外部包工具不受 Netizen 拦截，也不新增运行期版本检测。

退出确认包括服务管理器不会自动再拉起：macOS 已加载但无 PID 的 job 也须先卸载，
但恢复集合仍只含原运行实例。服务定义按冻结的已知格式校验，不以当前模板替代历史
契约。INSTALLER 是方式线索，不是普通环境的独占管理权；uv 临时缓存环境不接管，
uv tool 私有布局的窄版本门禁不扩散到使用公开接口的普通 uv pip。
替换范围外的协调器处理中断时先回收自己创建的子进程，再释放锁并留下未知状态；
不新增常驻恢复器，也不承诺 SIGKILL／断电后的自动补偿。

实例控制按 root，程序更新按环境。B 环境的 CLI 可以控制绑定 A 的服务，但 start／restart
仍执行 A；切换必须先 remove 保留数据、解除绑定，再从 B start 注册。不增加 rebind。
remove 默认保留数据，--purge 才删除经过归属和精确范围校验的实例文件；-y 只跳过交互
确认，不免除展示范围、退出确认和数据保护。永不递归删除整个 root／home，不删除 Project、
外来文件或共享 Codex 状态。程序卸载交给包管理器，用户先处理该环境所有关联服务。

Admin 只保留本实例重启，不再提供全局程序升级权限；一次性独立 manager job 与既有
管理员授权、ready 和失败对账边界保留。旧安装手工转换，不开发布局转换器，也不从
新版入口继续执行旧 release 安装链。发布仍须维护者显式触发，代码改造不授权发布或
迁移真实安装。实现状态与平台验收见 [CLI 部署](../cli.md)，不能以本决定代替验收。
旧部署实现、模板和旧事务专用测试退出当前代码；薄拒绝入口与历史 schema 夹具保留。
仅构建验收的发布 dispatch 不创建 Release draft；正式发布才进入外部发布链。
