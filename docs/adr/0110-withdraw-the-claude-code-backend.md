# 撤回 Claude Code 后端

## 背景

试点打通了飞书普通会话的顺序续聊、后台任务唤醒后的回答投递、手工改名和持久分支。只有实例所有者能执行这些操作，收益局限在单人场景。试点从未进入正式发行版。

Codex App Server 将 Thread 和 Turn 暴露为带标识的服务端对象。Netizen 能定向 steer 正在运行的 Turn，观察其终态，从目录读取 Thread，并委托原生归档、删除及 Goal 执行。Claude Agent SDK 为每个客户端启动一个 CLI 子进程，向调用方提供消息流，把会话记录写入本地文件。消息流缺少 Turn ID，客户端是否空闲需要推断，后台任务还会自行唤醒新的执行轮。外部写入者会使会话记录分叉，读取元数据需要在文件头尾做有界扫描。

因此，试点对准入、终态、会话身份及投递的保证依赖特定 SDK 和 CLI 版本的实测结果。每次上游升级都要重新证明这些条件，继续承担这项维护成本与试点的实际收益不相称。

## 决定

撤回 Claude Code 后端及仅由它使用的实现、配置、依赖和验证流程。Codex 成为唯一支持的后端。保留 ADR 0105 的五项决定在 Codex 上的应用：按实例固定后端并穷举装配，按调用方使用小接口，通过操作描述核对资格，填充共用展示模型，并维持既定执行不变量。保留 ADR 0106 的展示 Turn 及 ADR 0107 的飞书过程消息。本决定仅修订 ADR 0104 至 0107 中涉及 Claude 的部分，取代 ADR 0108、0109。

已有 Claude 实例使用其绑定的程序环境管理。新程序按通用的后端校验在数据库准备、迁移与执行准入之前拒绝启动该服务。按根目录执行 status、stop 和不带 purge 的 remove 遵循原有语义：配置、凭据、数据库等持久数据保留，锁、就绪标记和服务身份等临时状态随操作更新。环境升级后的启动失败沿用逐实例报告。

## 重新评估条件

出现实际用户需求，且 SDK 在以下方面有实质改进时，重新评估是否接入：服务端的会话和轮次标识及终态事件、无需读取本地文件头的会话目录和元数据接口、受支持的多客户端并发语义，以及面向多用户或第三方应用的受支持认证方式。届时根据实际契约另作决定；其他后端也从各自的原生契约出发设计。

## 后果

当前设计和使用文档只描述受支持的后端。移除试点专用的安装选项、CI 作业、原生验证与故障验收程序。Codex 的部署、能力及展示门禁继续执行，过程消息仍须通过适配器形状、合成和按需实时验证。
