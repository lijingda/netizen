# 根据聊天默认配置在原消息位置自动创建普通会话

需要用户先提交 `/new` 表单，阻碍自然语言输入直接进入自动化工作。新增聊天默认配置：
只有普通输入所在 Scope 没有当前 Binding 时，选择默认配置、建立 Binding，再提交原消息。
单聊主线、群聊主线或具体话题始终由真实入站消息决定；配置属于所属聊天，不创建另一话题。
手动 `/new` 的行为和预填保持不变，默认配置更新不传播到已创建的 Binding。

## 规则与管理

只提供同 App 的 exact chat 配置和有序群名条件规则。精确聊天配置最高优先；否则在群聊中
按保存顺序选择第一条非空关键词包含规则，关键词去除首尾空白并忽略字母大小写。
不引入类别默认、禁用自动创建、字段合并、正则、匹配评分或批量精确配置。匹配后配置
不可用不继续尝试后续规则；群名读取失败不能视为不匹配。群改名只影响之后的自动创建。

Project 必填；工作区策略独立表达创建意图，其余字段复用 SessionSettings：Model/Effort/Speed 的显式选择或继承，
Reaction Pulse、Progress Card、Completion Mention 和 Mention Context Mode。私聊与私聊
话题不支持 catch-up。保存和实际使用时按现有能力校验，不复制原生有效配置。

2026-10-20 扩展工作区策略，复用 [ADR 0085](0085-manage-worktrees-independently-of-sessions.md)
的共享 Worktree 服务：`project` 使用项目目录并保持历史默认，`existing` 引用 exact 受管
Worktree ID，`new` 为每个自动新建 Binding 创建 detached 工作区。`new` 允许可选 `ref`，
省略时使用实际创建时的 Project HEAD；只检出提交内容，不提供固定分支名或命名模板。
保存配置不创建工作区；已有 Binding 不重新执行策略。显式 `/new` 继续独立选择目录，
不读取默认规则。默认策略不改变 Worktree 的独立所有权或共享语义。

Admin 管理单条精确配置与群名规则，支持调整群名规则顺序。飞书 `/defaults` 只管理当前
聊天，话题内操作也明确作用于所属聊天；单张表单回填现有值、修改后保存，并提供删除
精确配置。无精确配置但命中群名规则时回填规则值，并说明保存将创建本聊天的精确配置；
均未命中时 Project 不预选，其他字段使用现有新建默认值。删除精确配置后重新匹配群名
规则，不删除来源规则。两端共享同一应用管理服务，保留原有鉴权和表单身份校验。

schema v14 开始在同一 Channel 数据库保存默认规则、显式配置意图、revision 与排序元数据；
v16 增加独立 `workspace_json`，通过冻结的 v15 → v16 迁移将旧规则设为 `project`。
迁移遵循 ADR 0076，Runtime 仍只接受当前完整 schema。不保存消息正文、卡片 session、
有效 Codex 配置或新队列。规则不参与 Project 或 Worktree 删除清单，不联动删除或禁用。
下次使用时仍按 Project alias 解析与能力校验判断可用性，不额外阻止同名 Project 重登记
后恢复；但 `existing` 同时校验 exact Worktree ID 与所属 Project 登记代次，同名 Project
或同路径新资源不能认领旧孤立工作区。保存、修改和删除默认规则都不删除工作区。

## 输入交接与并发

自动创建复用现有管理创建服务。在现有 Scope 锁内重读 current；已有 Binding 时直接
返回，缺失时同 Scope 的并发首消息共享一次创建结果。工作区 Git 准备在锁外执行，
Binding 提交前在锁内复核 current 与资源准入；不得为慢 Git 操作长期持有 Scope 锁。
手动创建仍可以新建并切换，自动创建不会覆盖其已提交的当前会话。消息固定其取得的目标，
继续沿用普通输入的精确 Binding/Turn/revision admission，不改投后来选中的 Binding。
若手动 `/new` 在工作区创建期间先提交，自动创建返回该已有 Binding，并仅向本次工作区
创建者提示未采用的新工作区已保留。已取得创建结果之后再切换则沿用原准入拒绝，不改投。

两个普通输入只能自动建立一个当前 Binding，`new` 策略也只创建一份工作区，但不承诺
都被接受或创建者先执行。共享的是进程内创建结果，不是 Prompt 或原生执行队列。自动
创建后手动提交 `/new` 可以再创建另一 Binding；原消息提交前发现切换仍拒绝并要求重发，
已经提交的任务保持原归属。没有新增串行消费、首轮优先、排队、合并、重试或另一套锁。

自动创建 catch-up Binding 的初始边界使用触发消息 A。A 同时是本次真实请求，仍需执行
一次；首轮复用当前消息、引用和图片准备，不读取 A 之前的补充历史。初始化标记只作用于
该创建请求，并参与同一上下文 revision 和输入准入校验；之后沿用普通 catch-up。不能把
设定初始边界视为 native 已接受，也不能全局放开相同起止消息的历史读取契约。

不构造虚假的 `/new` 消息或卡片提交，Current Prompt、sender attribution、Skill 输入和
结果投递锚点始终来自真实触发消息。命令、Side 路由/墓碑、定时交接保留各自入口，
不会因为没有普通 Binding 而转成自动创建；群消息的既有 @ 准入不变。

## 失败与验证

未匹配时沿用现有无会话引导。命中但默认配置失效时先解释原因，再给同样引导，不换规则。
Project 不可用、指定 Worktree 已删除、目录缺失或替换、状态无法确认均保留默认规则，
在使用时失败；不静默切到项目目录，不自动重建指定工作区。`new` 不引用此前创建的
工作区，此前资源被删除不使该策略失效；仍须重新校验当前 Project 与创建基线。
工作区创建成功而 Binding 创建失败时保留资源并反馈已知结果；未知创建不自动重试，
沿用共享 Worktree 服务的创建回执和管理恢复边界。
带资源副作用的创建失败或未知交接必须反馈，即使此时已出现另一个当前会话，也不继续
提交本条任务；资源保留提示本身发送失败不改变已确认的成功创建结果。
已经创建会话后，输入准备/执行失败保留该 Binding 并沿用现有失败处理，不重建、不自动
重放。现有会话的 unknown/unavailable 不等于缺少会话；归档或删除后 current 确实为空时，
新的普通消息可以重新自动创建，不自动恢复旧会话。

覆盖匹配顺序、App 隔离、保存/删除/排序竞态、失效默认值、群名查询失败、聊天/话题
身份、A/B 与手动创建交错、catch-up 首轮和后续边界、首轮失败、已有会话配置独立性以及
原 `/new` 行为；工作区扩展还覆盖三种策略、保存无创建副作用、资源缺失/替换、Project
同名重建与 Worktree 旧代次、并发首消息不重复创建、工作区已创建后的部分失败和未知结果。
仓库 gate 为 `make check`；真实卡片、Admin 和消息锚点的验收边界见
[部署文档](../deployment.md)，未执行的平台验证不得记录为通过。
