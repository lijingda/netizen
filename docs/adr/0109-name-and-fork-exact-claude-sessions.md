# 通过精确的 Claude 会话元数据改名和创建持久分支

Claude Code 进程会在后续输入中重新写入已加载的标题。持久分支会复制对话中记录的工具交换和会话 cron。开放这两项操作需要分别规定来源状态、写入确认和飞书交接条件。[ADR 0105](0105-extend-backends-through-capabilities-and-shared-presentation.md)

## 名称展示和手工改名

飞书状态、会话列表和 Admin 会话列表按 Binding 的原生 ID 有界读取公开的 `get_session_info(id)`。返回 ID 必须相同。有 `custom_title` 就显示原生名称，包括 Claude 自动生成的名称。只有 `summary` 时标为预览，两者均空或读取失败时显示 Binding 短 ID。读取只覆盖当次展示，不调用模型或保存副本。SDK 只读取文件首尾各 64 KiB，中间的标题可能退回预览或短 ID。自动标题沿用所有者环境中的 Claude 设置。

只有所有者能从飞书命令、手工保存卡片或 Admin 表单改名。目标必须已物化且其受管客户端已确认断开，打开、运行或等待准入的会话不能改名。保留客户端时提示用户等待后台工作结束。名称按既有规则合并空白，限制为 1 至 120 个字符。在准入锁内确认资格，工作线程调用一次公开的 `rename_session(id, name)`，再按同一 ID 复读 `custom_title`，完全相等才确认。名称同步显示在 Claude Code 的会话列表。

追加前的 SDK 参数或文件不存在错误是本次拒绝。其余异常、超时和回读不符报告“改名结果未确认”。调用者可以停止等待，实际工作线程结束前，竞争输入立即被拒绝。线程结束即释放准入，后续操作重新取证。Claude 的标题追加不改变执行状态，结果未确认仅影响本次改名。Codex 手工命名继续沿用其 Binding 生命周期隔离。两端均不自动重写。独立终端写入者不受宿主锁约束。[ADR 0067](0067-name-threads-with-private-ephemeral-forks.md)

## 精确持久分支

复用普通分支卡片的目标聊天校验、新话题与主线替换确认、原子 Binding 交接和回执。Claude 来源必须已物化，按普通续接方式由未指定目录的精确 ID 读取证明实际 cwd。打开中、物理轮运行中、输入待写或关闭未确认均拒绝。有受管客户端时必须确认有序 idle 且完整原生任务列表为空。仅有会话 cron 可以创建分支，卡片提示“来源会话设置的会话 cron 会随对话记录复制，新会话恢复时也会恢复。”[ADR 0078](0078-fork-persistent-sessions-and-trust-native-lifecycle-results.md) [ADR 0097](0097-fork-into-chat-main-lines-with-replacement-confirmation.md)

来源准入锁覆盖检查和一次有界的公开 `fork_session(id, directory=cwd, title=name)` 复制。名称为空时传 `None`，沿用原生默认。子 ID 必须是不同于来源的有效 UUID，并由未指定目录的精确子会话读取确认同一实际 cwd。保留客户端的活动修订号在复制期间有变化时，按已知子 ID 报告部分结果。该检查能发现已观测的原生唤醒，宿主没有跨进程快照锁。

复制前的参数或文件不存在错误是本次拒绝。复制结果未确认时不给出可执行 Binding，也不重试。已知子 ID 后核验、发布或绑定失败，回执保留 ID 供用户在 Claude Code 核查，来源会话保留，子会话也保留。完整交接继承来源 Project、worktree 关联及已有显式目录选择。校验所见的 cwd 只用于本次操作，后续续接仍独立读取原生元数据。Claude 无订阅交接、创建后归档或 Admin 分支入口。删除、创建时命名及显式生成候选名称留待独立决定。

## 固定版本证据、备选方案与复核条件

依据 SDK 0.2.186、随附 CLI 2.1.329 的既有回环记录。以下编号对应 D3-FACTS 的实验，同一轮仅使用可丢弃的会话与本地模型夹具。

- A1–A4、B5。关闭后改名、继续输入和压缩均可保留新标题。连接中的客户端在大输入后重写旧标题，后台任务存在时也会发生，因此即时回读不足以开放连接中改名。原生 AI 标题可由同一字段读出，所有者的流量与终端标题开关会影响生成。见 `pressure-cold-close`、`pressure-resumed-close`、`background-pressure`、`ai-nonessential-valid-verbatim`。
- B6–B7、C11。`/btw`、`/branch` 在逐字交付时进入普通输入，启用原生命令分派后在该客户端被拒绝。私有非持久 fork 可以生成候选，但另需模型请求和独立执行归属。手工改名仅开放标题写入。见 `btw-idle-dispatch`、`branch-idle-dispatch`、`private`。
- C8–C10。关闭来源的持久 fork 可精确续接且来源字节保持一致。原生任务仍运行时，子会话收到该任务陈旧的停止通知。前台工具调用中复制可能缺少相应工具结果。复制前需要有序空闲和空任务列表。冷分支也会恢复同一个会话 cron，单凭禁止从保留 cron 的客户端复制不能防止恢复，因此向用户明确披露。证据仅证明登记恢复。见 `persistent`、`background`、`mid`、`cron-closed`。
- C12。大图首记录中的 cwd 可能超出读取窗口，带目录查询可回显调用方提供的目录。来源或子会话缺少独立 cwd 证据时停止交接。见 `images`。

SDK 或随附 CLI 升级时复核上述证据。若公开接口提供能协调现有写入者的改名或快照保证、可靠的大记录元数据，或任务与 cron 的复制恢复行为改变，在原生回环验证后重新决定对应限制。真实账号和飞书客户端验收独立记录。
