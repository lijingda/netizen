# 按用户独立存储并按需读取 Admin 飞书凭证

飞书签发的有效 token 已超过本地字段长度限制，导致用户确认授权后仍无法登录。
原有聚合文件还要求启动加载全部用户凭证，并在单用户变化时重写其他用户的数据。
改为每个 `App ID + Open ID` 独立文件、实际使用时读取，初期不增加驻留缓存；同时删除
用户 token、scope、用户凭据文件和飞书认证响应的任意大小接受阈值。

每个用户使用 `credentials/admin-user-<sha256>.json`，摘要是 UTF-8 编码的
`App ID + "\n" + Open ID` 的完整 SHA-256 十六进制值。文件保存版本 `1`、App ID、Open ID、
成员 addRevision、UAT/RT 及各自期限、scope 和 `refreshAttempted`。文件内容仍须与路径
对应的准确身份及当前成员代次匹配，不以文件存在证明管理员资格。启动不扫描或解析用户
凭证；读取仅涉及当前用户，异常文件只使对应操作失败，不扩大为服务启动或其他用户故障。
局部管理操作仍不依赖 UAT；只有实际调用飞书时才读取、检查期限及刷新。

每用户串行锁只在操作及等待期间存在，避免同一 RT 并发消费，不持有 token 缓存。
保留单服务 writer、网络期间释放名单锁、刷新前持久化尝试标记及成功后的原子替换。
网络失败、取消或结果未知不得再次消费已尝试的旧 RT；新登录可以覆盖恢复。提交仍须
核对当前成员代次及登录有效性，删除后重添不接受旧凭证或迟到结果。删除管理员先撤销
资格和会话，再精确清理该用户文件；清理失败不恢复权限。目录和文件的私有权限、属主、
普通文件、单硬链接、无符号链接及原子写校验保留。

取消用户 token 长度、scope 长度和条目数量、用户凭据文件 1 MiB、飞书认证响应 64 KiB
限制，不以猜测的上游长度拒绝有效凭据。字段类型、控制字符、期限和文件结构仍校验；
Admin 入站 HTTP、管理员名单和应用配置的独立限制不变。响应仍先完整读入并解析，保留
必要字段后释放其余内容，因此更大的响应仍有相应的临时内存与解析成本；此变更不承诺
流式读取或恒定内存。固定上游地址、超时及禁止重定向等协议边界继续沿用 ADR 0080。

不读取、不迁移旧 `credentials/admin-user-tokens.json`，也不自动删除。用户明确接受
升级重启后重新完成飞书登录，以避免只为可重新获得的凭证增加双格式维护。浏览器 session
本来就随重启失效，磁盘 token 不能替匿名浏览器证明身份；名单、Project 与原生会话数据
均不受影响。新登录直接生成新格式，后续重启保留这些独立文件。显式 `remove --purge`
精确识别新格式文件，并继续包含旧聚合文件；未知文件不纳入清理，不增加数据库、缓存
索引、迁移状态或后台扫描。
