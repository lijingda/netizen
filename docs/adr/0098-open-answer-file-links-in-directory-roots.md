# Admin 对话记录中的本地文件链接按所在目录只读打开

## 背景

Codex 的最终回答经常用 Markdown 链接引用本地文件。Codex 自己的格式要求是“绝对路径目标，
可在目标内带行号”，例如 `[app.py](/abs/path/app.py:12)`。Admin 对话记录（ADR 0096）目前把
这类链接渲染成静态文本，管理员只能去 Project 的“查看文件”里手动逐级找到它，而回答引用的
文件常在 Project 目录之外（如 `/tmp` 下的报告）。

ADR 0089 把查看根限定为 Project 登记目录与同一登记代次的受管 worktree。这条限制管的是
“查看 Project 当前目录”这个功能的范围和根身份的正确性，并不是针对管理员的安全边界：
登记 Project 只要求目录存在且服务账号可读、可写、可进入，任何实例管理员都能把服务账号的
home 目录登记为 Project，进而查看其中的实例凭据、Codex 登录信息和 SSH 私钥。所有实例
管理员权限相同，没有角色或 Project ACL（ADR 0031/0080）。

## 决定

### 链接识别

对话记录最终回答（最新轮与更早轮）中目标为绝对路径的 Markdown 链接可以点击。行号可选，
支持 `:行`、`:行:列`、`:行-行` 与 `#L行` 写法；末尾 `/` 表示目录。识别在渲染时完成，只做
字符串解析，不访问文件系统或数据库，也不检查文件是否存在。相对路径链接、行内代码中的
路径和 `file:` 链接保持静态。路径含 `.git` 段或位于 `/proc`、`/sys`、`/dev` 下的链接保持
静态，悬停时说明原因。原文降级页不生成链接。

### 目录根

点击后打开共享文件查看器，以链接所在目录（目录链接则为该目录本身）为根，定位到该文件，
有行号时在源码中跳到该行。根在打开时解析一次符号链接，与登记 Project 时的做法相同；服务端
返回规范路径与 device/inode 身份，后续请求携带规范路径和身份，不再重新解析，身份不符时
要求重新打开。根内沿用 ADR 0089 的全部读取规则：按目录描述符逐段打开、不跟随符号链接、
不开放 `.git`、只读普通文件、相同的大小与条目上限、无下载。目标缺失时显示查看器的现有
错误，不回退到上级目录，也不搜索。

不按已登记的 Project 匹配链接：位于 Project 内的链接同样以所在目录为根打开，不提供 Project
目录树、相对 HEAD 的差异（ADR 0095）或 worktree 切换。打开的是文件当前内容，不是该轮
快照，也不改变飞书 Files 的 exact Turn 证据。

### 读取范围与信任模型

目录根可以是服务账号可读的任意目录，`/proc`、`/sys`、`/dev` 除外；每次请求都按规范根与
相对路径组合出的绝对路径检查这一点。实例管理员通过文件查看能读到的范围，等于服务账号
的读权限。不设敏感路径黑名单：黑名单无法列全，只会造成已受保护的错觉。加强权限应落在
谁能成为管理员以及登录本身（ADR 0080），而不是收窄查看范围。部署与使用文档须写明这一点。

### 隔离与资源

目录根的全部文件系统操作（包括打开时解析根目录）都在一个独立的有界执行器中运行
（2 workers、4 个在途/排队 slot），与 Project、附件查看和对话记录排版共用的执行器分开。
网络挂载失联时卡住的读取只影响这一类查看。不新增缓存、索引、轮询或 Channel SQLite 数据。

## 被拒绝的方案

- **只匹配本会话 Project 或所有已登记 Project。** 按上文不带来安全收益；渲染时要查 Project 与
  worktree 登记，使对话记录依赖其状态；Project 外的链接仍然打不开。
- **以 `/` 为根展示整机目录树。** 每一层上级目录都必须可列出且不是符号链接，深路径要连续
  列出多层目录。
- **敏感路径黑名单。** 无法列全，见上文。
- **每次请求重新解析符号链接。** 引入第二套路径语义；只在打开时解析一次，与 Project 登记一致。
- **渲染时检查文件是否存在。** 会把文件系统访问放进对话记录的渲染路径。

## 后果

- 管理员会话泄露后，可读范围是服务账号可读的全部文件。这与登记 home 目录已能达到的范围
  基本相同，额外包括 `/etc` 等只读位置和共享主机上其他用户可读的文件。
- 多了一组文件查看接口，认证、错误码和预算须与 Project、附件保持一致；共享读取规则只放在
  底层读取函数里，不在各类根里各写一份。
- 卡在失联挂载上的读取无法被超时取消，进程退出时仍可能等待它，与现有文件查看相同。
- Project 内的链接打开后看不到 Project 视图。以后若需要，可另行把命中已登记 Project 的链接
  改由 Project 查看器打开，不改变目录根。
