# Admin 文件查看显示相对 HEAD 的未提交变更

> 修订说明：v0.18.0 发布后，下文“两个视图”中独立的变更视图及其三个分组改为目录树上的
> “只看变更”过滤：只过滤已加载层级并与完整目录共用展开状态，删除项按快照补行，已忽略项
> 不参与过滤；查看方式合并为源码、预览与差异一组切换，差异增加分栏/合并与折叠未改动区域。
> 整个根目录仍只查询一次 status，不逐层查询；Git 读取、隔离与有界规则不变。当前交互以
> [工程设计](../design.md#project-未提交变更)为准。

## 背景

ADR 0089 让管理员只读查看 Project 当前目录，但只能看完整文件，看不出改了哪里。飞书
本轮文件只给路径和行数，ADR 0027/0053 明确不提供预览或 diff。服务器部署后，用户缺少
一个审阅改动的地方。

GitHub 式 diff 比较两个不可变提交，结果可以长期缓存；Admin 浏览的是随时变化的工作区，
Netizen 也不保存 Turn diff、历史、内容缓存或 Git 状态。因此唯一可用的基准是所选根所在
仓库的当前 HEAD。

## 决定

### 基准与范围

1. 只比较所选根内工作区当前内容与当前 HEAD，不区分暂存和未暂存。基准提交和旧内容的
   blob 都取自同一次 status 输出（`# branch.oid` 与该路径记录中的 HEAD 对象），不另行
   解析 HEAD。单文件差异返回所用提交，与变更列表不一致时提示刷新，不混用两个基准。
   尚无提交的仓库以空树为基准。
2. 这是 Git 事实，不是 Codex 事实：其中包含人工修改和同目录其他会话的并发修改，不对应
   任何 Turn，也不改变 exact Turn Files 与本轮行数统计。界面须写明“相对 HEAD”。
3. 首期只做源码差异。不做任意 ref/提交/merge-base 比较，不做 Markdown 或图片的 rich
   diff，不提供 patch 导出、下载，也不提供暂存、提交、回滚等写操作。完整模式下现有
   Markdown 预览不变。只对 Project 开启，输入附件浏览不受影响。
4. 不持久化 HEAD、基点或状态，不缓存、不索引、不轮询；刷新时重读。

### Git 可用性与非 Git 根

root 响应保持 ADR 0089 原样。Git 信息凭已选根的身份另行异步请求，结果为 `available`、
`not_repository` 或 `unavailable`，不阻塞目录树。Git 明确报告不是仓库时按非 Git 处理：
隐藏所有 Git 入口，体验与 ADR 0089 相同。其他失败（未安装、超时、所有权检查拒绝等）
为 `unavailable`：变更入口显示暂不可用并可重试。是否为仓库以 Git 自身的发现为准，不另做
元数据检测，也不放宽 `safe.directory`；部分损坏的仓库可能被 Git 判为非仓库，此时只是
没有 Git 入口。任何 Git 失败都不影响目录树和内容读取。

Git 调用始终以所选根（或缩小后的目录）为 pathspec，并把仓库根相对路径换算为根相对路径；
所选根位于仓库子目录时，默认根仍不提升到仓库根。不进入子模块和嵌套仓库：嵌套仓库按
外层 Git 的报告显示为一条未跟踪目录，子模块不出现在变更中。两者内部的文件照常可看完整
内容，但没有状态和差异。

### 两个视图

目录树仍表示文件系统事实（ADR 0089：含未跟踪、已忽略和隐藏文件），只增加修改、新增、
未跟踪标记，已忽略项灰显。变更视图表示 Git 报告的候选路径，分三组：已跟踪变更、未跟踪
（默认展开）、已忽略（默认收起；被忽略的目录只显示一条，点击跳到目录树，不在列表内展开）。
已忽略项不平铺进变更，是为了不让依赖、构建产物和日志淹没真正的改动，同时保留查看被
忽略草稿的场景。

Git 状态码分别描述 HEAD→暂存区和暂存区→工作区，不等于相对 HEAD 的净变化，所以只用
来确定候选路径：同一路径的多条记录合并为一条，类别只看 HEAD 中有没有该路径、工作区有
没有该文件。

- 两侧都有：修改。从变更视图打开时默认显示差异，从目录树打开时默认显示完整内容，两者
  可切换；内容相同时显示“与 HEAD 相同”。
- 只有 HEAD 有：删除。只能从变更视图进入，显示整篇删除。
- 只有工作区有：新增、未跟踪或已忽略。以完整模式打开。

只有 Git 为该路径本身报告了记录时才提供差异。

### 读取通道与执行隔离

旧内容来自 Git 对象库，这是 ADR 0089 描述符读取之外唯一新增的读取通道：只按 status
给出的 blob 读取 HEAD 中与根内路径对应的内容，不开放 `.git` 目录项、对象、ref 或日志
浏览；路径沿用 ADR 0089 的校验。它会暴露已删除文件在 HEAD 中的内容；管理员权力相同、
没有 Project ACL，接受这一扩展。

工作区一侧继续使用描述符相对、不跟随链接的有界读取。两侧都必须满足现有文本上限
（UTF-8、1 MiB、10,000 行、单行 20,000 字符），HEAD 一侧先查 blob 大小再读取。超限、
二进制、符号链接、对象缺失或仅模式变化只显示变化类型，不读取或跟随目标，也不退化为
部分差异。两侧全文交给浏览器，由随包的 Ace 1.45.2 官方 `ext-diff` 计算并显示（宽屏
分栏，窄屏行内），沿用现有 Ace 的懒加载方式；服务端不解析 Git patch。

仓库配置与 `.gitattributes` 可能由 Agent 写入，一次查看不得执行任何仓库配置的程序。
Git 调用复用受管 worktree 后端的隔离运行器：禁用 hooks、fsmonitor、全局 attributes 和
untracked cache，置空所有已配置的 filter helper，清除 `GIT_*` 选择变量，关闭终端提示，
使用独立进程组、超时与输出上限。查看时还设置 `GIT_NO_LAZY_FETCH=1` 和空的
`GIT_ALLOW_PROTOCOL`：部分克隆缺失的对象不触发自动补抓，任何传输都不能启动；这只
作用于查看，不影响 worktree 后端已有的显式 fetch。命令只用定位仓库和读取 filter 名称的
只读 `rev-parse`/`config` 查询、`--no-optional-locks` 下不写 index 且带
`--ignore-submodules=all` 的 `status --porcelain=v2 -z`，以及按 blob 读取、不带
`--filters`/`--textconv` 的 `cat-file`；不使用会触发外部 diff 或 textconv 的命令。

filter helper 被置空是隔离的已知代价：使用 LFS、git-crypt、nbstripout 等 filter 的文件
可能被报告为已修改，差异按原始字节比较；不得为此恢复 filter。Git 结果与文件读取一样，
在执行前后复核根身份和登记代次。

### 有界与性能

成本主要靠机制控制。Git 信息异步加载，不阻塞目录树。单文件差异按需进行，以该路径的
status 确认候选和基准，不依赖变更列表是否完整。变更列表可限定到某个目录，同时减少 Git
计算和输出。Git 进程不占用文件读取执行器：沿用现有异步运行器（取消时结束整个进程组），
另设实例级并发上限 2，超出时返回繁忙；文件读取仍使用 ADR 0089 的 2 并发 / 4 在途预算。

上限只作兜底：边读 status 输出边计数，达到上限（默认 10,000 条，以大仓库实测确定）即
停止读取并结束 Git，结果标为不完整。Git 依次输出已跟踪、未跟踪和已忽略记录，未读到的
分组显示为未完整加载。目录树上没有标记不能被理解为未修改。超时返回明确的状态读取超时。

## 考虑过的方案

- **Turn 级 diff**：需要保存 Turn diff 或历史，违反 Channel 数据契约。
- **服务端运行 `git diff` 并解析 patch**：工作区一侧会改由 Git 读取，还要处理外部 diff
  配置和 patch 格式；改为两侧全文加浏览器计算。
- **分页**：每页都要重跑完整状态，页间工作区还可能变化；保持一致需要服务端快照，违反
  无缓存约束。以按目录限定代替。
- **缓存、索引或后台监听**：工作区可变，无法安全失效，且违反 ADR 0089。
- **启用 fsmonitor 或 untracked cache 加速**：前者会运行配置的程序或守护进程，后者需要
  写 index。超大仓库靠超时和按目录限定。
- **自行检测损坏的仓库元数据**：要另写一套仓库发现逻辑，收益只是在少见的损坏场景下把
  “非 Git”改报为“不可用”；以 Git 自身的判断为准。

## 后果

管理员可以在 Admin 审阅工作区相对 HEAD 的改动，但它不代表某个会话或 Turn 的贡献。读取
面扩展到 HEAD 中已删除文件的内容。功能依赖服务主机上的 `git` 可执行文件，缺失时只是
`unavailable`。包内增加一个 Ace 资源，需在 vendor 说明中记录校验和，并列入认证静态资源
路由和包资源验证。

代码门禁：
- 隔离：恶意 diff driver、textconv、filter、fsmonitor、hooks 和部分克隆自动补抓的合成
  仓库，均不执行仓库配置的程序。
- 仓库形态：三种 Git 状态，子目录根的 pathspec，空仓库，嵌套仓库与子模块。
- 类别判定：状态码与净变化不一致的路径（改回原文、`git rm --cached`），超限、二进制、
  对象缺失与模式变化，HEAD 变化提示。
- 有界：达到上限时截断并结束 Git；Git 繁忙或超时不影响目录与内容读取。
- 前端：切换文件、根、模式和刷新时的竞态，窄屏。

隔离浏览器集成验证与真实飞书 WebView 验收分别记录。
