# 将首次飞书应用初始化与终端输入解耦

公开安装入口已经要求 Agent 下载脚本后以 `</dev/null` 执行，但首次缺凭据仍因没有 TTY
直接退出，迫使用户手工创建应用、交接 Secret；现有官方 `register_app` 并不读取 stdin。
决定把 ADR 0044 的浏览器能力与终端输入分离原则扩展到首次初始化和显式应用重绑定。
无需新增安装参数、Agent 专用入口、Lark CLI 依赖或另一套授权协议。

## 入口与身份

Published Release 与 Source Install 的公开零参数入口，在候选验证及 Codex 登录检查通过后，
凭据不完整时都允许启动一次官方浏览器流程。无 TTY 时直接启动；有 TTY 时保留默认浏览器的
安装方式菜单与手工输入选项。TTY 只决定菜单和手工凭据输入能力，不代表用户不能在浏览器
确认。linger 和旧 system service 等实际需要输入或管理员准备的步骤保留原门禁。

应用身份继续遵守 ADR 0035：首次未绑定不传 `app_id` 或 `create_only`，由官方页面创建或
复用应用；有效 App ID 对应的 Secret 文件存在但为空时传 exact App ID，返回必须为同一
应用。有效 App ID 的 Secret 文件被显式删除仍表示重置绑定，无 TTY 时同样允许官方页面
重新创建或选择，成功前保持文件不存在。安装器不枚举应用或自行实现选择器。

ADR 0057 的 Admin Upgrade 保持例外：后台执行者缺配置、凭据或权限时返回
`requires_action`，不能因共享安装器支持无 TTY 就发起浏览器授权。管理员应在公开安装入口
完成修复，再显式重试 Admin 操作。

## 有界确认与激活

验证 URL、二维码和进度只进入 stderr；父进程仍私下捕获 helper stdout、校验返回 shape
与应用身份，再原子保存受保护凭据。Agent 转交链接并保留同一进程，用户在官方页面确认，
无需通过聊天或可写 stdin 交接 Secret。SDK、最小 tenant addons、无 user token 和凭据
不进入 argv、环境、YAML、unit、日志的边界保持。

每次安装最多发起一次浏览器流程，沿用 660 秒父进程 deadline。无 TTY 的失败、取消和超时
直接终止，不尝试 `input`/`getpass`，不循环发起链接，不进入 activation；有 TTY 的浏览器
失败保留手工回退，Ctrl-C 仍中止。首次初始化或重绑定成功后不立即发起第二次补权流程。
已有完整凭据的 exact-App 补权继续沿用 ADR 0044：修复后重新查询一次有效 tenant 权限。

浏览器确认仅完成应用配置，成功取得凭据仍必须通过有效 tenant 权限门禁才能准备 host 和
激活。审批、发布、租户安装、可用范围与入群仍是明确的外部步骤。新凭据一旦成功写入就是
持久配置意图；后续权限失败或候选回滚不会恢复旧凭据，保留 ADR 0035 的两阶段语义及
ADR 0034 的唯一 activation/rollback 事务。

## 取舍

公开安装在无 TTY 的首次配置处可能等待最多 660 秒，而不再立即给出手工补全错误；换来
Agent 与人类使用同一官方确认流程、减少手工漏配和 Secret 交接。调用方必须及时转交中间
输出并保留进程；工具不支持时由用户直接运行安装器或使用手工凭据备用路径。无人确认的
执行有界失败，不暗示配置或部署完成。

仅要求 Agent 使用 PTY 会把产品的正常初始化能力绑定到命令工具差异，并让 README 的
零输入命令继续失效；因此不作为默认解决方案。本 ADR 不声明版本已经发布或 live 验收
通过，验收路径见[部署文档](../deployment.md#浏览器安装路径验收)。
