# 在可移除的实验模块中实现自主消息准入

本决定只适用于自主模式实验分支，不表示 main 已支持或正式发布。用户选择在独立分支实现已确认设计，
以验证决策模型而不让普通执行流程依赖它；比将第三种值混入通用 @ 上下文模式更容易合并和移除。

## 输入和执行边界

仅为自主 Binding 的真人未 @ 群消息增加前置 consume／skip 判断。唯一 Channel 可以收到未 @ 事件，
但应用层按 exact Scope／Binding 过滤，其他模式、私聊、Side 与明确控制入口保持原有行为。
分类前固定原生 admission，返回与准备输入后重新校验；不得重选 Binding、把结束 Turn 的跟进变成新 Turn，
或把普通讨论解析为未获准的控制命令。故障不放行，不缓存等待重放，不发送逐条 skip／故障通知。

模型选中后仍只提交当前消息及原有显式引用／附件；可附加未消费用户消息条数，不自动引入被跳过正文。
显式 @ 绕过决策，仍遵守原生接收条件。自主记录错误不取消已接收任务或阻断回复。

## 窄持久化例外

在唯一 Channel SQLite 内增加 `autonomy_` 专属结构，由同一 Store 连接／事务拥有，按 Binding ID 关联。
允许保存自主开关／修订、接收序号、已被 Runtime 接收的当前消息投影、实际最终正文及有界文本摘要。
不保存被跳过候选正文、过程活动、固定提及或文件模块，不复制原生 Thread／Turn 历史及完整查询结果。
删除 Binding 同事务清理专属数据；关闭模式保留记录，关闭期间不收集、不补录。

这是对主文档“不保存其他消息正文”的明确有限例外，不是第二个历史系统或改文件存储规避契约。
保持 `MentionContextMode=current-only|catch-up`；自主实验开关独立，启用时只能使用 current-only。
开关变更推进既有 context revision，沿用 stale 卡片和原生 admission 防护，不传播到 Scheduled Plan／Side 设置。

## 配置、摘要和退出

Admin 通过同一管理服务维护受保护的决策连接 profile，密钥不进入 YAML、SQLite、聊天、日志或状态响应。
保存校验并持久化后更新本进程，下一次判断使用新配置；不监听文件变化。无配置不影响基础服务启动。
原有会话卡片仅选择模式，缺少配置时确认提交失败而不创建或部分修改会话。

摘要使用现有共享 AsyncCodex 创建新的 ephemeral Thread，只提交指定决策记录，不复制用户完整 Thread。
独立有界收尾临时资源，普通任务不等待摘要收尾；提示约束不被宣称为工具权限隔离。

正式移除时保留普通 Binding、Thread、历史与工作成果，明确回到 @／current-only，清理实验配置与专属数据。
禁用／清除连接使在途自主结果失效，原有已接收 Turn 继续；恢复只处理新消息。
schema 仍严格按当前版本校验；合入／退场的数据转换需显式设计，不能拿任意旧版本或整库历史快照替代。

## 验证

覆盖默认行为不变、显式 @／控制绕过、consume／skip／不可用、精确 admission 竞态、模式切换、
最终正文过滤、计数／摘要一致性、凭据保护、Admin 认证与提交修订、关闭后无迟到触发及临时资源清理。
执行 `make check`；真实模型效果、未 @ 飞书事件投递和原生 ephemeral 生命周期需要另行 live 证据。
