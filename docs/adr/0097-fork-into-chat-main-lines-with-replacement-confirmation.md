# 持久分支可落到聊天主线，替换当前会话前确认

ADR 0078 的 `/fork` 只在目标聊天新建话题。有两类“换个位置继续当前会话”的需求落不到
话题里：飞书话题内的回复属于话题本身，不能逐条引用，需要大量引用的会话只能回到群聊
或单聊主线继续；所在群不再使用时，用户希望在另一个聊天的主线继续同一段工作。

## 落点

`/fork` 在既有“当前聊天、选择群聊、聊天 ID”三选一之外增加落点：“新话题”（默认，
行为不变）或“主线”。主线指群聊主线或单聊主线，对应目标聊天的 GROUP/DIRECT Scope。
在话题中选择当前聊天主线，即所属群聊或单聊的主线。不接入已有话题。

以下情况在原生副作用前拒绝并保留表单：目标主线 Scope 与来源 Scope 相同（来源已在
该主线）；目标为话题群（`chat_mode=topic` 或 `group_message_type=thread`），它没有主线。

## 替换确认与指针语义

提交校验阶段在原生 fork 之前读取目标主线的当前指针，这一步没有副作用：

- 为空时直接创建。
- 非空时把卡片刷新为只读确认态，展示目标聊天、当前会话名称、编号和运行状态，说明它
  会保留在会话列表中、可以切回，并提示两条现有规则的后果：被替换会话正在等待提问
  回答时，需要切回后才能作答；它的原会话定时计划会因不再是当前会话而自动暂停。确认态
  只有“确认创建”和“返回修改”两个按钮，草稿由按钮 callback value 携带，不保存卡片
  session。“确认创建”只能提交确认卡上展示的同一份草稿；返回修改后再次提交会重新检查
  目标主线。

确认表示同意替换提交时该主线的当前会话（如果有），不绑定确认卡展示的那一个。确认后到
提交前，指针变空、切到别的会话或被新建会话占用，都不再次确认；检查时为空、未经确认
就进入创建的路径遇到同样竞态，也直接替换。替换不丢失会话，被替换者仍可从会话列表切回。

落库复用 `/new` 的指针语义：在目标 Scope 锁内重读实际当前会话，原子保存完整 Binding
并设为当前，被替换的 Binding 保留。随后在同一把锁内执行与 `/new`、`/resume` 相同的
指针交接，按 ADR 0028 保护新的当前会话，并让被替换的空闲会话立即尝试释放订阅。不对
确认时的快照做比较交换：比较失败只会发生在原生 fork 已经创建之后，只能留下未绑定的
Thread，比直接替换更差。

被替换会话上仍在准备的消息沿用“准备期间 active 会话已切换”的拒绝，不改投分支；已在
运行的任务继续执行，并在原锚点交付；之后主线的新消息进入分支，不再 steer 旧任务。这些
都与 `/new` 替换时的行为一致，问题回答与原会话定时计划也继续按现有规则处理。

## 主线交接

主线没有根话题。原生 fork 之后，在目标主线发布唯一的“创建中”状态消息，用确定性 UUID
做发送去重。它承担新话题根卡的职责：结果展示、来源回执中的跳转目标，以及群聊 catch-up
的初始边界。单聊仍固定为 current-only。完整交接成功后原地更新这条消息，写明实际被替换
的会话（没有则不提）及切回方式；目标聊天的成员靠它知道当前会话已经变化。Binding 已
保存但交接未完成时，失败消息同样写明被替换的会话。

## 创建后归档来源

表单增加“创建后：保留当前会话／归档当前会话”，默认保留。分支完整交接成功后才执行
归档。勾选就表示同意归档，和替换确认一样，不再复核来源的运行状态或设置。原生 archive
的准入只看 Binding 是否指向已物化的持久 Thread，不看运行态或 idle；为自动步骤另加空闲
门禁会违背这一契约。fork 创建期间如果来源开始了新任务，归档会交给 App Server 一并
shutdown，和在会话列表里归档运行中的会话相同。归档可以恢复，不是删除。

归档复用会话列表的 exact archive：在 exact Binding/native 身份下预留 lifecycle intent，
释放锁后委托 App Server。来源
仍是当前会话时清空来源指针，否则保持来源指针不变。明确拒绝只报告原因；服务停止或来源
已不存在等在原生调用之前就失败的情况，报告本次未归档；结果未知时，按既有 Binding-local
lifecycle-unknown 处理。任何归档结果都不撤销分支，也不自动重试。归档期间，来源回执先
显示分支已创建、正在归档来源，归档返回后再更新为最终结果。

其余沿用 ADR 0078：来源资格、历史与设置继承、在途所有权、失败与人工核查边界、卡片
去重。新话题落点仍要求目标话题未被占用。表单协议升级到 v6，只解析当前协议。

## 备选方案

- **真正迁移（改写 Binding 的 Scope）**：可以保留 Thread ID、会话编号、定时计划和 Goal，
  但会打破“Binding 属于创建它的 Scope”这一隐含不变量。散布在多个模块的 Scope 身份比较、
  来源聊天里的旧卡片都要逐一审计，跨聊天拉取还需要新的来源授权语义。扩展落点不改写已有
  Binding，就能覆盖两类主要场景。若定时计划跟随或 ID 保持成为明确需求，再重新评估。
- **接入已有话题**：卡片无法列出某个聊天的话题，话题里既有的飞书讨论也不在上下文中。
  确有需要时，应作为“在目标位置拉取会话”单独设计。
- **其他聊天的主线只在为空时允许**：统一的确认更简单。被替换会话可以切回，目标主线的
  状态消息让该聊天成员知情。

## 代价

- 分支是新的 Thread 和会话编号，来源上的原会话定时计划、Goal 和协作工具引用都不跟随；
  来源归档后，它的定时计划自动暂停。
- 分支引用来源历史时，Codex 可能拒绝删除来源（ADR 0078），归档的来源可能长期保留。
- 替换会改变目标主线成员下一条 @ 的去向，靠确认态和状态消息缓解，不新增权限层。目标
  校验沿用 ADR 0078，只核验机器人可访问，不核验操作者是否为目标聊天成员。

## 验证

行为测试覆盖：新话题落点行为不变；主线为空时直接创建；非空时确认、返回修改，以及确认后
指针变空、切换、被新建会话占用；同 Scope 与话题群拒绝；指针交接与订阅释放；被替换会话
准备中的消息被拒、运行中的任务继续交付；catch-up 边界取状态消息；单聊固定 current-only；
归档来源的成功、明确拒绝、未知，以及创建期间来源开始新任务后照常归档。不新增原生调用类型；真实飞书的
群主线与单聊主线落点、状态消息、v6 表单和确认态单独验收。
