# 在结果正文中预览明确引用的本地图片

成功终态的 Result 直接读取正文 Markdown 图片节点引用的本地图片，上传后改写为飞书
image key。该图片不必是本轮生成或修改的文件。Files 仍只使用既有 native Turn 证据，
列表、分页和“发送”行为不变；正文预览不调用文件提取、不扫描目录，也不添加 Files 条目。
这是对 ADR 0024/0027 不自动上传约定的显式展示扩展，不是放宽 Files 的证据规则。

使用固定版本 markdown-it-py 解析图片 token，修改后交给 mdformat 的 MDRenderer 输出。
显式启用其 GFM 插件以保持表格、删除线和任务列表语义，不启用外部代码格式化器或读取
用户格式化配置。不自建源码位置映射；接受 Markdown 空白、换行、列表和引用写法的规范化，
不承诺非图片源码逐字符不变。没有改写任何图片时直接保留原文。代码示例、普通链接不触发
图片读取；不下载网络图片或 data URI。

绝对路径直接使用，相对路径按普通会话的 Project cwd、Side 捕获的 cwd 或 Goal 最终
结果的 cwd 解析。支持本地 file: URL；不接受带主机名的 file URL。只读取服务进程可访问
的普通 PNG/JPEG/GIF/WebP 图片，不将文本文件按图片上传。缺失、不可读、非图片、超限
或上传失败只在对应位置显示可读提示；外部取消仍向上传递。正文引用是这里明确允许的
读取来源，不能再描述为经过 native Turn 文件证据确认；服务读取也不声称经过 Codex 工具审批。

通过 Channel SDK 公开 upload_media 上传后，将 `![说明](image_key)` 正文交回原输出流程。
固定 SDK 默认 native 模式将普通回复写入 `post` 的 `tag:md`，卡片使用既有 Markdown 组件；
两者均承载该图片引用。图片处理只返回正文，不选择消息类型、不构造新的卡片或 post AST，
也不接管 SDK 的分段、提及、路由、重试或投递回执。
同一次 completion 按 canonical 路径去重，失败不重试；最多 20 张，单图 10 MiB、
累计读取预算 50 MiB，共享 8 秒准备预算，每次读取及上传最多 4 秒。读取前预留预算，
成功后归还未用额度，失败或超时不归还。图片准备失败不改变原生执行结果。
卡片图片语法见[飞书 Card 2.0 文档](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-json-v2-components/content-components/rich-text)。

普通/Side 在没有 Files 且进度卡关闭时，保持原富文本/静态回复；是否使用卡片仍仅由
原有 Goal、Activity、Files 规则决定，不由正文是否含图决定。
既有 v4/v5 正文 manifest 自然保存 image key，翻页与服务重启不重新上传；不存在新的
callback 版本、持久状态或缓存。卡片失败回退复用同一次准备，保留已经上传的图片引用，
沿用原富文本发送和完成提醒，不因退出卡片而把可用图片换成提示。
定时任务未知投递继续保持 unknown，不重复发布。
正文显示上传时图片；Files 按钮仍发送点击时当前文件，两者不保证是同一版本。

本地验证覆盖图片节点改写、GFM/飞书标签的代表性语义、代码排除、路径与缺失文件、
上传边界、无 Files 仍为富文本、分段/首段提及/话题路由、各完成出口和重启分页。
真实飞书客户端的显示、放大、整卡更新及降级仍需目标应用验收；本地测试不能替代。
