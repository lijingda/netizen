# 未配置过程卡的会话使用实例级兜底

过程卡已有会话与聊天默认配置，但固定的展示默认值无法由管理员统一调整。将该默认值
变为本实例的全局过程卡配置，仅供没有显式过程卡设置的会话使用；保留聊天默认规则的
创建时复制语义，不增加动态规则继承或覆盖已有会话的批量操作。

## 配置意图与捕获

完整 SessionSettings 的 `progress_card_settings` 可为完整八字段对象或 null；null 表示
未配置。聊天默认配置与定时新话题配置原样复制该意图；手动 `/new` 默认未配置。
普通新 Turn、Goal 新 logical run 和 Side 创建时，优先采用显式设置，否则读取全局值，
随 Task Feedback 一次性冻结。运行中 steer、Goal 换物理 Turn 和已有 Side 后续输入
继续使用已捕获值；有效值不回写 Binding、默认规则或计划。卡片分页仍使用自身快照。

已有值一律视为显式选择，包括与原默认值相同的值，不推测来源、不重置历史配置。
schema v19 保留 v18 的表结构，仅放开持久配置语义：Binding 的既有 TEXT 字段可保存
JSON null，完整 SessionSettings 的相应字段也可为 null。冻结的 v18 → v19 步骤不修改
已有值；更早的迁移仍按原规则回填显式默认值。启动迁移沿用 ADR 0076，不保存过程历史。

## 实例配置与入口

既有实例 `config.yaml` 的 `progressCard` 保存完整八项设置；缺少该节时使用原工厂默认值。
Admin 在“系统管理 → 过程卡”展示“全局过程卡配置”，复用现有内容开关、容量与组织方式
控件，提供保存和放弃修改。`/api/v1/progress-card/settings` 读写共用现有 Admin 登录、
同源检查、一次性操作授权和 revision 冲突保护；共享 `ConfigFileEditor` 原子保存 YAML，
写入成功后才更新进程内值，外部文件变化仍按现有规则拒绝覆盖。没有新的配置文件或历史模型。

Admin 会话与默认配置表单在未配置时显示全局值作为编辑参考；仅编辑过程卡细项才生成
显式对象，保存其他选项或切换过程卡总开关不会固化全局值。飞书 `/new`、`/config`、
`/defaults` 和定时任务表单不增加细项控件，读写与重绘均保留未配置意图。
本轮不增加重置或跟随开关，也不改变过程卡总开关、其他回复模块及既有 55,000 bytes
检查和超限交付策略。

## 验证边界

本地验证覆盖缺省 YAML、严格字段校验、写入失败与冲突、历史值保留、null 持久化与迁移、
各入口的意图保留、全局值捕获及后续修改隔离，以及 Admin 全局表单和已有表单的保存行为。
仓库门禁仍为 `make check`；真实浏览器与飞书客户端按部署手册另验。此处记录验证范围，
不表示这些检查已完成，也不因实例展示配置变化触发无关原生 live phases。
