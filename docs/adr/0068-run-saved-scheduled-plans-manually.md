# 通过现有调度链路手动执行已保存的计划

2026-09-23 修订：[ADR 0070](0070-schedule-inputs-in-existing-bindings.md) 将已保存版本的
手动运行扩展到 exact Binding 目标；不接受任意即时 Prompt，但可按保存的计划 steer。

创建、修改计划后的试跑以及临时执行需要直接使用计划已保存的指令和配置。用户确认
Admin、`/cron` 和自然语言均提供“立即运行”，并采用同一 Scheduled Run 与普通会话
执行链路。自然语言在现有 `cron_manage` 增加 `run_now`，继续按名称定位、exact ID
执行，不增加工具、意图分类层、基础 Skill 或第二套 Runtime。

`run_now` 只接受计划 ID、当前 revision 与稳定 request_id；不接收临时指令、配置或
投递目标。Admin 的例外限于启动已保存的计划版本，不能提交任意即时 Prompt 或 steer。
暂停及当前规则已结束的计划仍可手动执行；计划启停、时间规则、下次到期点、高水位和
revision 均不因此改变。Project 停用、删除和应用身份边界继续适用。

手动请求与到期点使用同一事务内的计划屏障，首轮未结束或结果未知时拒绝新的手动认领；
定时到期继续按原规则记录 busy/unknown 并推进游标。成功认领后，由唯一 Scheduler
管理交接、停机排空和 Project 删除协调，复用相同 Channel/Runtime。计划快照在认领时
冻结，后续编辑或删除不取消已认领执行。手动来源不会伪造真人 Prompt、授权或结束提及对象。

手动请求以 request_id 去重，七天内重试返回原 Run ID，即使计划已修改、删除或执行记录
已裁剪也不重新交接。定时触发仍以 `(plan_id, due_at)` 去重，唯一约束只作用于定时来源；
手动请求不能占用、消费或伪造定时到期点。Run 仅增加 `scheduled/manual` 来源，管理
去重回执仅增加可空 Run ID，不保存新一份指令、响应或原生终态。

工具和 UI 的成功回执表示请求已受理，执行结果仍在计划目标会话的新话题交付。原生
状态沿用 exact initial Turn 的有界读取；响应未知时按原请求核查，不自动生成新请求。
Admin 保持既有一次性 action/CSRF grant，响应丢失后先查看最近执行，不扩展认证协议。

schema 升为 v12。项目尚未推广，维护者明确不承担历史数据库自动升级，因此撤销
ADR 0063 的安装期窄迁移，不保留 v10/v11 转换代码或旧字段兼容分支。服务与安装器
只接受当前完整结构，新库直接创建；旧版本及损坏数据库明确拒绝，不自动清空或重建。
本机旧数据需要时单独停服、备份并一次性转换，不成为产品内的迁移路径。安装仍保留
target 卸载、lifetime lock、数据库快照和失败恢复数据库/release/Skill 的原有边界。

验收覆盖三个入口、CAS/请求重试、手动与定时竞争、停机恢复与排空、Project 生命周期、
快照及来源、记录裁剪后的回执、当前库重装、旧库只读拒绝与安装回滚。自然语言的真实工具使用
与飞书客户端渲染分别验证，不以替身测试冒充端到端兼容性。
