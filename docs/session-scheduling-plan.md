# 原会话定时输入实施计划

依据 [ADR 0070](adr/0070-schedule-inputs-in-existing-bindings.md)。目标是在保存的 exact
Binding 中按普通消息规则 start/steer，复用配置、catch-up 与反馈；保留新话题模式和
普通 Runtime 的故障边界。此清单用于组织本次实施，完成情况以代码与实际验证为准。

## 实施增量

- [x] 存储与调度：执行目标、当前 schema、同 Binding 多次交接、原会话独立到期点、
  接收与业务终态分离、未知不重发不阻塞下一次、重启收敛。
- [x] 生命周期：手动启停与目标可用性分离、切换/归档暂停、恢复不补跑、删除联动。
- [x] 管理入口：Service/MCP、`/cron`、Admin 选择 exact Binding，原会话配置继承、
  创建后目标固定、有效暂停和输入接收结果展示。
- [x] 共同消费：真实锚点、Scheduled Plan 来源、普通准备/准入/start/steer/反馈与异常，
  catch-up upper 和 cursor commit，系统来源新 Turn 无结束 @。
- [x] 行为验证：普通/Goal start-steer、精确身份竞态、锚点失败、配置与反馈继承、
  生命周期、幂等和故障恢复；现有新话题模式回归。
- [x] 文档与最终检查：领域词汇、设计、用户手册、部署验收记录，`make check`、
  `git diff --check`、独立评审及 SDK live 验证。
- [ ] 外部验收：真实飞书主线/话题锚点、catch-up、卡片/通知与生命周期联动；
  目标主机安装和失败回滚。需要明确测试目标，不由本次源码实现自动执行。

## 验证边界

本地替身测试证明行为和竞态，SDK live 证明真实原生调用；真实飞书锚点、消息容器、
catch-up 可见性、客户端通知与卡片渲染需要各自的真实环境证据，不能互相替代。
不因实现完成自动发布、升级或转换现存数据库。

兼容性检查），`git diff --check` 通过；独立评审发现的准入捕获与发送取消问题已修复
并覆盖。新增 17 项真实 Runtime/替身传输集成测试覆盖普通和 Goal 输入交接、catch-up、

Thread 的上下文继承、start、exact steer 和清理；详细范围见

新话题表单。补齐真实卡片回调、丢失回执重试、非当前目标选择及查询故障/恢复测试，
增量独立复核通过；更新后的 `make check` 全部通过（2116 项测试及全部后续检查），
