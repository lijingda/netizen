# 让会话之间协作

[手册目录](user-guide.md) · [会话与 Project](sessions.md)

可以直接请求：“新建一个话题研究接口兼容性，你继续处理主任务，等它回答后汇总。”
Netizen 会在当前聊天中新建普通话题。来源已经是话题时，新建的是同一聊天里的另一个
话题，原会话保持不变。新会话继承来源 Project 和工作目录，因此文件修改相互可见；
它有独立对话上下文，不复制来源历史，也不创建独立 worktree。

新会话默认继承来源模型，也可明确要求另一可用模型。过程卡沿用来源设置，表情闪烁和
结束时 @ 提醒关闭。创建后可以像普通会话一样继续输入、修改配置、停止、归档或删除。
需要带上原有上下文时使用已有的 [`/fork`](fork-side-goal.md#fork-持久分支)。

可以提供标题；名称在后台处理，未提供时自动生成。命名失败不影响创建回执和任务，
无名时继续用编号或预览辨认；后续新一轮对话会按现有规则尝试补名。

## 查找和引用目标

开启发现权限时，可以说“读取接口调研会话的结论”或“把这个问题交给测试会话”。
候选仅包括当前 Netizen 实例登记的普通会话，可以跨聊天、跨 Project；同名且无法唯一
确定时需要澄清。独立 CLI/App 创建而未登记到本实例的会话、Side 和子 agent 不在目录中。

可以直接提供完整 **Codex 会话 ID（Thread ID）**，例如“读取 Codex 会话 `<完整 ID>`
最近的回答”。在 `/status` 详情、`/sessions`、归档列表或 Admin 的标识区域取得完整值；
查看 ID 不需要把目标切回当前。不要把 **Netizen 会话编号（Binding ID）** 或飞书聊天/
话题 ID 填成跨会话目标；短 Netizen 编号继续用于原有 `/resume` 等人工控制。
尚未收到首条任务的空会话可能还没有 Codex 会话 ID，界面会明确提示。

飞书没有新增 `@会话` 选择语法。标题用来查找，完整 ID 用来确定目标；话题链接只能
打开位置，因为同一个话题里可能切换过多个会话。

## 来信、等待与人工干预

向另一会话发送时，目标话题会出现注明来源的机器人消息。原生 Codex 在接收时决定
启动一轮，还是把来信加入正在执行的普通任务；它保留工具来源，不冒充真人发言。
发送回执只确认接受，不代表任务完成；协调会话可继续读取或等待结果。
读取历史默认保留协作来信的来源会话 ID 和正文，无需展开所有工具输出。

任务反馈仍在普通话题中展示，可以在那里直接干预。若目标已被切到后台，工具会说明
状态，发送不会自动切换、恢复归档或改投另一个会话。已存在的后台历史可在权限允许时
读取。正在停止、压缩或其他不可接收状态会说明原因，系统不自动重发未知结果的请求。

当前 SDK 限制下，正在执行 Goal 的会话不能接收这类协作来信；真人在目标话题里的
正常补充仍按原有规则处理。Goal 预检失败或状态未确认时，回执会明确说明来信未提交。

## 管理可访问范围

实例管理员在 Admin 设置两组独立范围，所有来源聊天共用：

- **发现**：决定哪些聊天的普通会话可以列出或按名查找。单独开启只返回定位元信息。
- **读取与发送**：决定哪些聊天的普通会话可以读取、发送或等待，也约束新建话题的首条任务。

每组支持全部、仅指定聊天、排除指定聊天、关闭，默认全部。关闭发现但允许读取与发送
时，可以直接提供完整 Codex 会话 ID。知道 ID 不会绕过范围限制。名单按目标聊天 ID
匹配，覆盖其普通主线与话题。权限在每次工具开始执行时检查；调整范围从下一次调用
生效，不撤销正在处理的调用，也不停止已经接受的任务。

这组设置控制会话协作工具，不改变普通飞书消息的准入或其他原生工具权限。
