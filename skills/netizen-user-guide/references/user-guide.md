# Netizen 飞书用户手册

每个 Netizen 机器人在部署时选定一个后端。默认后端是 Codex，Claude Code 试点供所有者本人使用。
飞书提供消息、卡片和会话入口。在 Codex 实例中，任务、原生 Thread 和 Turn、历史、工具、Skills、MCP、权限与 sandbox 由 Codex 管理。

用 `/help` 查看当前实例开放的命令，Claude 实例的帮助以“Claude 会话”开头。用 `/status` 查看当前会话和任务状态。

## 快速开始

以下步骤适用于 Codex 实例。请先确认部署者已完成飞书应用授权、发布与可用范围设置，群聊还需加入机器人。如果没有可选
Project，先通过 `/projects` 登记已有工作目录或创建项目并启用，再开始下面的步骤。

1. 发送 `/new`，在卡片中选择项目。不确定模型配置时可选择“继承 Codex”，也可选择
   Model（模型）、Effort（思考强度）和 Speed（速度）；回复消息类型默认为卡片，结束时 @ 提醒默认开启，执行中表情闪烁
   默认关闭，可分别调整。
   群聊和群话题还可选择 @ 时读取的消息范围。`/new` 不接受参数。
   默认使用项目目录；Git 项目可先加载 worktree 选项，再[选择或新建受管 worktree](sessions.md#选择受管-worktree)。
2. 创建成功后直接发送任务，例如“梳理这个项目的结构”。创建会话本身不会启动任务。
3. 普通任务或 Goal 执行中继续发送消息，会补充到当前正在执行的 Turn，不会排队成下一轮；
   恰好完成或换轮时会提示重发，启动、停止、收尾或压缩期间会拒绝普通消息。
4. 用 `/status` 查看当前会话、任务、原生执行步骤和上下文窗口；用 `/sessions` 查看同一聊天或
   话题中的其他会话，并可在卡片中直接将其设为当前。
5. 用 `/help` 查看当前实例此刻开放的命令。

如果当前聊天已有可用的[会话默认配置](sessions.md#默认会话配置与自动创建)，还没有当前会话时可以
直接发送任务：机器人会在消息所在主线或话题创建会话并处理这条任务，无需先发 `/new`。
默认配置可选择项目目录、指定已有受管 worktree，或为每个新会话新建 worktree；保存配置
不会立即创建 worktree。所选资源失效时会说明原因，请修改配置或手动准备会话后重发任务。
已有当前会话时继续使用它，不再读取默认配置；`/new` 始终保留原有手动创建行为。

需要按时间重复执行时可创建[定时任务](scheduled-tasks.md)。新话题计划独立选择项目目录、
已有 worktree 或每次执行新建 worktree；原会话计划沿用目标会话的实际目录。

没有匹配的默认配置时，机器人会给出原有下一步：没有已启用项目时先去 `/projects`，有
项目时通过 `/new` 创建会话；当前聊天或话题已有会话记录时，还会提示 `/sessions` 和
`/sessions archived` 查找并切换或恢复。默认配置不可用时会先说明原因，再给出这些提示。
**被拦下的任务尚未执行，准备好会话后请重新发送。** 系统不会自动创建项目或重放任务。

`/help` 顶部提供快速开始，命令按开始与设置、任务操作、会话管理分组。未知命令会提示
查看帮助；误用 `/project` 会指向项目管理入口 `/projects`，不会执行项目操作。
命令格式或参数错误会给出用法提示；`/projects` 和 `/new` 都不接受参数。

群聊主线和群话题中，每一条触发机器人的消息都必须重新 `@机器人`。单聊以及单聊中的
话题无需 `@`。即使选择“自动带上期间的群聊讨论”，未 @ 的消息也只可能在下一次 @ 时
作为背景进入 Codex，不会让机器人自动响应。

同群其他机器人也可以通过真实 `@Netizen` 提交任务或补充正在执行的任务，发送者仍标注
为机器人。飞书应用需开通并发布 `im:message.group_at_msg.include_bot:readonly` 权限；
CLI setup 默认申请并检查此权限；已有应用缺失时，由部署者在 setup 中完成补权，
Admin 不执行应用绑定或程序升级。机器人的未 @ 消息不会自动加入“期间的群聊讨论”。

## Claude Code 试点

只有实例所有者（setup 时绑定的唯一飞书管理员）能发起任务、更改设置或操作卡片。在允许使用机器人的聊天中，
其他人只能单独发送纯文本 `/help`，不能附带参数、引用或附件。群聊和群话题中的每次操作都要 @机器人。
Admin 只向所有者开放，无法添加第二名管理员。

1. 先用 `/projects` 选择或登记项目，再发 `/new` 选择项目目录或受管 worktree。创建后发送第一条任务，
   可以附图。用 `/sessions` 查看本聊天或话题中已登记的普通会话，用 `/resume` 切换。
   `/config` 和 `/defaults` 可调整群聊消息范围、回复消息类型、执行中表情，以及任务完成或失败时是否 @ 本轮发起人。
2. 运行时可以看到“正在输入”和任务状态表情。机器人确认本轮结果后立即投递，回复中引用的本地图片会尽量直接显示。用 `/status` 查看本地任务状态和已建立的 Claude 会话 ID。
   状态卡和 Admin 会显示最近观测到的模型、token 数、费用与额度，以及各自的采样时间。
   服务重启或样本被淘汰后会显示“未观测”；当前上下文占用显示“取不到”。`/sessions` 按本地登记时间列出会话。
   如果已收到回复但状态仍为“正在收尾”，请等会话空闲再发下一条。这段时间没有停止按钮。
   CLI 空闲且后台仍运行时可以继续发消息。看到“当前会话正在执行，本条消息未发送。”时，等这轮结束再发。
   服务启动时，机器人连上飞书后还要等两秒才能接收任务。过早提交会收到“服务刚启动，请稍后重发”。这两种情况下都需要自己重发。
3. 发送 `/stop` 中断当前轮。回执会列出当前观测到的后台任务数。要连同已列出的后台任务一起停止，发送 `/stop all`，也可点状态卡上的「全部停止」。会话 cron 保留。
   如果这轮已经结束，迟到的停止请求不会中断下一轮。若收到“本次 Claude 提交结果未知”，先检查原会话和
   实际工作目录，确认之前的操作是否已生效。系统不会自动重发。客户端已关闭时，可以向原会话发送下一条指令。
   若提示无法确认客户端已关闭，该会话暂停接收输入；服务确认客户端已关闭后，会话恢复接收输入。

**在终端续接。** 如需在终端继续这个会话，请先 `/release`。前台正在执行时，等本轮完成或先发 `/stop`。如果卡片列出后台任务或会话 cron，核对数量后点「确认释放」。释放会结束该连接上的后台任务，暂停 cron 并保留登记。收到已释放或没有连接可释放的提示后，从 `/status` 复制 Claude 会话 ID。用同一系统账号，在该会话的实际工作目录
（选了 worktree 就进入那个 worktree）运行 `claude --resume <会话ID>`。退出终端里的会话后，再回飞书发送下一条消息。如果原会话或目录找不到，先检查账号、ID 和目录。
同一目录里的不同会话可以各自执行。

如果先在终端继续了对话，下一条飞书消息可能收到「会话在其他客户端有新进展」卡片。该消息尚未发送。要接上终端的进展，点「释放会话」，等确认后自己重发。如需继续使用 Netizen 当前的连接，直接重新发送即可。飞书保有后台工作时，旧连接可能在检查前被任务唤醒，写出会话分支，导致当前历史里看不到终端的新对话。

**已知限制。** 首条消息带较大的图片时，Claude 可能保存了对话，但 SDK 读不到会话摘要。飞书无法确认原工作目录时会拒绝续接，
请检查原会话，或用 `/new` 新建会话。首次写入前崩溃也可能使会话无法续接，原会话仍会阻止删除所属 Project。

**权限与反馈。** 每轮都由 Claude Code 按原生设置管理模型和工具权限。Netizen 申请 `auto` 模式，
即使项目设置关闭了自动审核，Claude Code 启动时仍可能报告 `auto`。如果 Claude Code 在本轮结果中报告操作被拒绝，
机器人会在回复前提示被拒绝的操作数，并列出可识别的工具名，例如 `Bash`。如需放行，请在 Claude Code 设置中调整权限规则。
如果 Claude Code 启动时报告使用默认权限，机器人也会提示未预先允许的操作会被拒绝。两种情况同时出现时，只发一条提示。
若提示无法确认权限模式，请按结果未知处理。飞书端没有逐步审批或原生提问卡。

**查看过程和文件。** 卡片和过程消息都能显示 Claude 的工具操作、子任务数量和本轮报告的任务清单。操作时间是机器人收到更新的时间。续接后可以看到这次连接中新建的步骤。更早的任务要等 Claude 列出完整清单才会显示。成功结束后，Claude 在本轮直接写入、编辑的文件和笔记本可以从「本轮文件」发送；子任务、命令和第三方工具的产物不列在这里。只有文件、没有文字回答时，也会收到文件卡。

**后台任务。** 首答和后台完成轮分别回复发起任务的消息。选择卡片时，每个有回答的物理轮单独回复，最新一张卡的执行过程栏会更新状态。选择过程消息时，只有这条输入仍有后台任务，文字回复末尾才会显示其数量。自己的后台任务全部结束后，按设置在最后一条已确认的回复上提醒一次。后台唤醒或原生定时触发的轮次在结束时投递，运行时没有单独的过程消息。原生定时触发的回答发到当前聊天或话题。可用 `/status` 核对任务数。

**试点范围。** 飞书和 Admin 均未开放 Goal、Side、持久分支、原生会话归档／删除／恢复、会话协作、定时任务和
原生历史读取。飞书也不提供模型／思考强度／速度选择、额度查询、上下文压缩或内置 Skills。已建立 Claude 原生会话的 Project 会在删除预览时被拦下。

若工具启动了后台进程（例如开发服务器），Linux 的 systemd 服务退出时会清理同一 cgroup 内的进程。
macOS 的 LaunchAgent 崩溃后，已脱离的工具进程可能继续运行。重做任务前先检查已有进程和文件，
尤其是会写文件、启动服务的操作。
