## 新建与配置 Project

- `/new`：打开唯一的新建卡片。Project 下拉框展示全部 enabled Projects，不由 Netizen
  截断或分页；Model 可继承 Codex，也可显式选择 Model、Effort 和 Speed。Reaction Pulse
  默认关闭，Progress Card 默认开启，可独立选择；群聊和群话题还可选择 @ 时读取的消息范围。
  同 Scope 当前或最近使用且仍 enabled 的 Project 可能被预选；没有历史偏好时需要明确
  选择。提交后创建并切换 Lazy 会话；没有 enabled Project 时会引导先打开 `/settings`。
  新会话的过程卡细项默认未单独配置，执行时使用本实例的[全局过程卡配置](admin.md#全局过程卡配置)。
- 任何带参数的 `/new ...` 快捷创建都已下线；请在卡片中选择。
- `/settings`：打开实例设置卡片。当前可在 Projects 分区启用、停用、创建或登记 Project。
- 停用 Project 只阻止用它创建新会话，已有会话仍可继续；Netizen 不会删除 Project 目录。

## 选择受管 worktree

worktree 是同一 Git 仓库的一份独立检出，不属于某个会话私有。多个会话可共享它的文件
与分支；项目归属不变，实际工作目录变为所选 worktree 中的对应目录。

1. 发送 `/new`。默认“项目目录（不使用 worktree）”，不会自动沿用上个会话的 worktree。
2. 若尚未加载或切换了 Project，在顶部唯一的项目选项中选择项目，再到下方“worktree”点击
   “加载 worktree 选项”。这一步只查询，不创建会话；保留已填写的模型、上下文和反馈配置，
   worktree 选项重新默认选中“项目目录（不使用 worktree）”。非 Git 项目不显示 worktree 与分支选项。
3. 在创建表单中选择“项目目录（不使用 worktree）”、“新建 worktree”或已有 worktree；
   已有选项按“已有 worktree · 分支 · 路径”展示，直接使用当前分支，不会因下方的新建配置切分支。
4. 新建默认从 Project 当前 HEAD 检出 detached worktree；可改为检出未占用的本地分支，
   或填写新分支名并选择起点。远端分支可作起点，不能作为已有本地分支检出。
5. 提交后仍只创建 Lazy 会话，首条任务或 Goal 才启动 Codex。新建 worktree 只含提交中的
   文件，不复制未提交改动、未跟踪/忽略文件，也不执行环境初始化。

若 Project 登记的目录因切分支等操作而缺失，请先修复 Project；即使另一个 worktree
目录仍存在，`/new` 也不会借它绕过 Project 检查。

若 worktree 已创建但会话创建失败，它会保留，可在 Admin 管理或之后 `/new` 再选。确认尚未
开始创建的失败不留下待清理登记；可能已经开始的创建失败仍保留已知证据。创建结果
未知时先查看已知登记和目录，不要重复提交。被手工删除、路径身份改变或无法确认状态的
worktree 不可用于新会话；已有会话保留历史和原 cwd，后续请求按 Codex 实际返回处理，
不会自动切回项目目录或恢复文件。

只展示通过本 Netizen 实例新功能登记的 worktree，不自动导入 shell Git、App/CLI 或其他
实例的 worktree。配置和删除见 [Admin 管理](admin.md#worktree-配置与管理)；没有飞书
`/worktree` 管理命令。`/fork` 本版不增加新建/选择 worktree 功能，仍继承来源实际目录。

## 默认会话配置与自动创建

`/defaults` 打开当前聊天的一张配置表单，无需先创建会话。在话题中发送时，设置作用于
所属群聊或单聊，供该聊天的主线与普通话题之后创建会话时使用；卡片会显示这一作用范围。

- 已有当前聊天的精确配置：直接回填到表单，修改任意项后保存；也可以删除精确配置。
- 没有精确配置但命中群名规则：回填继承的配置，并说明保存会为当前聊天建立精确配置，
  不会改动群名规则。
- 都没有：显示尚未配置，选择必填的 Project 后保存；其余选项沿用新建会话默认值。

表单包括 Project、worktree 使用方式、模型／思考强度／速度、三个任务反馈选项，以及群聊的消息
读取范围。模型可以继承 Codex；单聊及其话题固定只读取当前消息。
Admin 默认会话配置还可调整[过程卡内容、数量、摘要长度和组织方式](feedback-and-files.md#配置过程卡内容)，
显式设置随自动创建复制到新会话，之后独立维护；未单独配置时，新会话使用本实例的
全局过程卡配置。飞书表单保存时保留已有细项或未配置状态，不会把当时的全局值固定下来。

| worktree 使用方式 | 自动创建新会话时的行为 |
| --- | --- |
| 项目目录（不使用 worktree） | 使用 Project 登记的目录。 |
| 使用已有 worktree | 使用所选受管 worktree；多个会话共享其中的文件和分支。 |
| 每个新会话新建 worktree | 为这个新会话创建 detached worktree，后续消息继续复用。可以指定起点 revision；留空时使用创建时的 Project HEAD。 |

后两项只适用于 Git 项目。新建 worktree 只带已提交内容，不复制未提交改动或未跟踪文件，
也不自动安装依赖。保存默认配置本身不创建会话或 worktree，也不启动任务。`/new` 保持原有
表单和预选行为，不从这里预填；`/config` 仍用于修改当前会话。

Admin 可以逐条配置具体群聊或单聊，也可以按“群名包含关键词”设置有序规则。优先采用
具体聊天的精确配置；没有精确配置时，按群名规则的顺序取第一条命中项。关键词不能为空，
英文匹配不区分大小写，不支持正则、群聊／单聊类别兜底、精确配置批量设置或禁用覆盖项。
群名规则适用于之后遇到的匹配群聊，无需预先为每个群配置。

Admin 的“默认会话配置”页分为“指定聊天”和“群名匹配”两个 Tab，各自以列表展示，
暂不提供过滤条件。“指定聊天”包含单聊与群聊配置；“群名匹配”按实际优先级排列，
可通过上移、下移调整顺序。点击添加或编辑会打开右侧抽屉，保存后保留当前 Tab 和分页
位置；删除当前页最后一条配置时会回退到上一页。
指定聊天时先选择群聊或单聊。群聊可以在选择框中输入群名搜索，支持继续加载候选，也可
手动输入聊天 ID；只提供机器人当前已加入且可访问的群。单聊继续输入聊天 ID（不是用户
ID），输入旁提供官方获取指南；也可在目标单聊中使用 `/defaults` 直接配置该聊天，无需查 ID。编辑已有配置不会更换目标；
暂时无法确认类型时保留原 ID。群名匹配仍填写关键词。

删除精确配置后会重新匹配群名规则，所以删除并不等于关闭自动创建。默认值、规则顺序或
群名的修改只影响之后的自动创建，不改变已有会话。归档或删除当前会话后，下一条任务仍可
按默认配置创建新会话，不会自动恢复旧会话；状态暂时不可用的已有会话不会被替换。

命中配置的 Project 已停用、删除，模型设置失效，或指定 worktree 已删除、目录缺失或
无法确认时，会先说明“默认会话配置不可用”，再给出原有手动准备会话的提示；本条任务
不执行，不尝试下一条规则、不改用项目目录，也不自动重建指定 worktree。需要匹配群名但
读取失败时，也会说明无法判断。

Project 或 worktree 删除不自动清理默认配置，需通过 `/defaults` 或 Admin 修改、删除。
Project 重新以同名登记后，项目目录策略可以恢复使用；“使用已有 worktree”仍认原来的
资源身份，同名 Project 或同路径新 worktree 不会自动替代它，须重新选择有效 worktree。
“每个新会话新建 worktree”不依赖此前创建的 worktree；旧 worktree 被删除不影响策略本身。
修改或删除默认配置不会删除已有 worktree。
会话已创建后的输入或任务失败继续按原有规则处理，保留会话，不自动重放失败消息。
如果 worktree 已经建好、会话创建却失败，系统会说明已知结果并保留 worktree，可在 Admin
管理或之后的 `/new` 中复用；结果未知时不会自动重试创建。

自动创建沿用现有的逐条 @、输入准备和并发规则；两条同时到达的消息不会各自自动创建
一个会话或重复新建 worktree，但不保证先触发创建的消息先执行，发生状态竞争时仍可能提示重发。群聊中的
每条触发消息仍需 @，控制命令和 Side 不触发这项自动创建。

## 查找、切换和命名会话

- `/sessions`：用分页卡片列出当前 Scope 的普通会话。当前会话明确标记，若不在当页会独立展示；其他会话可点击
  “设为当前”；这只切换后续普通消息默认进入的会话，不会停止其他会话正在运行的任务。
  所有 persisted materialized 历史行无论是 idle、running、stopping、Turn 观测不可用、
  Goal 或 Compaction，都可“归档”或打开独立红色确认卡后“删除”；App Server 自己处理
  当前原生活动。普通 Turn 行还可 exact“停止”，`turn-observation-unavailable` 行可
  “重新检查”。空闲 Lazy 行仍可删除，但只删除本地 Binding。归档/删除非当前行不会改变
  当前会话；操作当前行会清空当前会话指针。
  会话优先显示原生名称，无名称时使用首条消息预览，并始终保留切换所需的短 ID。
  默认按原生最近更新时间分页，使用上一页、下一页或刷新首页；尚未开始的 Lazy 会话
  有独立入口。查询失败会明确提示，任务运行状态暂时读不到时显示“暂不可用”。
  目录暂未列出的会话不代表已删除，已知编号时仍可用 `/resume`。
  普通、归档及未开始列表均提示可发送 `/admin` 打开 Admin 会话列表，进行更多筛选与集中管理；
  若分页信息或整卡内容过长，仍会明确报错。
  `/threads` 是兼容别名。
- `/sessions archived`：列出当前 Scope 的已归档会话，可恢复并切换，也可通过独立红色
  二阶段确认永久删除；删除直接使用与 active Thread 相同的 App Server primitive，不先恢复。
  按原生最近更新时间分页，范围仍为当前 Scope，不限制当前 Project；目录不可用时明确报告查询失败。
- `/resume <短 ID>`：按保存的原生会话 ID 恢复并切换，成功后提示“已恢复并切换”。
  会话暂未出现在原生列表中并不妨碍恢复，包括刚创建、尚未发送新消息的持久分支。
  已归档、不存在、被占用或正在关闭时，按原生返回提示原因并保留当前会话。尚未开始
  对话、尚无原生历史的 `/new` 会话只做本地切换。结果未知时按提示交由部署者处理，
  不会自动重试。
- `/rename [名称]`：重命名当前原生 Thread；省略名称时打开卡片。名称也会显示在 Codex App/CLI。
  未命名会话会在新 Turn 启动后根据当前上下文后台生成名称，运行中补充消息不会重复触发。
  已有名称保持不变，手动改名优先。自动生成失败不影响聊天，失败确认结束后下次新 Turn 会再尝试。
  手动改名会等待已有名称写入完成后覆盖，无需因自动命名而重试；等待不阻塞聊天或其他会话操作。
- `/release`：显式取消当前 active 普通会话在本 Netizen 连接上的订阅。它保留 Binding、
  原生 Thread、历史、配置和 Task Feedback，下一条普通消息仍 resume 同一 native ID。
  运行中、状态未知或有已登记后台 terminal 时会拒绝；Side 使用 `/side close`。

这里的短 ID 是 **Netizen 会话编号（Binding ID）** 的前缀，只用于当前 Scope 中的会话
选择。不能拿另一个聊天或话题里的短 ID 跨 Scope 切换。**Codex 会话 ID（Thread ID）**
则是完整原生标识，供[会话协作工具](session-collaboration.md)指定目标；列表和状态详情
会明确区分两者，并提供完整原生 ID 文本。查看后台或归档会话的 ID 不需要先切换或恢复。

## 归档、恢复和删除

- `/archive`：确认后把当前 persisted 原生 Thread 直接交给 App Server 归档；Turn、Goal、
  Compaction 或观测故障都不剥夺该控制。归档保留会话配置与 Task Feedback，并清空
  当前会话指针；不会自动切换到另一会话。
- `/unarchive <短 ID>`：恢复已归档会话并切换到它，与归档卡的“恢复并切换”相同。
  会话已解除归档时仍可继续切换；已是当前会话时保留现有群聊补充消息边界。正常运行中
  的原任务会继续，不会因为切换重新启动；停止、压缩或状态未确认时按提示处理。
  找不到可恢复记录、无法取得会话或正在关闭时，保留本地关联和原当前会话，不自动重试。
  若先解除归档成功、后续切换失败，会明确报告部分结果；若本地切换结果未确认，应按
  提示核查，不能据此认定当前会话未变。结果未知只隔离目标会话，其他会话仍可使用。
- `/delete`：Lazy 会话二次确认后只永久删除本地 Binding；已有原生历史的 persisted 会话
  会显示带 exact Thread identity 的更强红色确认，并直接委托 App Server 处理当前活动。确认后
  永久删除原生 Thread、App Server 管理的 spawned descendants、Codex App/CLI 历史与
  本地 Binding，无法恢复。
- 删除以本次 Codex 返回为准：成功才清除本地关联；明确拒绝会保留会话并说明原因，处理
  原因后可重新确认。请求结果未知时只隔离目标会话，其他会话仍可使用；不会自动再次
  删除或用列表中找不到会话来判断删除成功。原生可能已停止该会话的活动，拒绝不保证
  原任务仍在运行。
- 若持久分支仍引用来源历史，Codex 可能拒绝删除来源；删除来源不会自动删除独立分支。
  按提示先处理仍引用它的分支，再重新确认，不会强制复制或脱离历史。
- 删除或归档一个会话不会自动删除它使用的受管 worktree；目录在 Admin 单独管理。

如果提示会话被其他 Codex 实例占用，当前步骤未能取得会话，其他会话和管理功能仍可使用。
恢复操作若已完成解除归档，会另行说明，不能把部分成功理解为整个操作都未执行。
请在占用该会话的 Codex App 内归档，或在占用它的交互 CLI 内执行 `/archive`，然后回到
原飞书聊天或话题，通过 `/sessions archived` 的“恢复并切换”或 `/unarchive <短 ID>`
恢复原会话并重发消息。归档会结束目标会话及其子会话的运行活动；App 托管的 worktree
还可能被清理。不要另开一个独立 CLI 执行归档来尝试抢占。若直接退出占用该会话的独立
CLI，待其释放后也可以在飞书重发消息，无须归档。真正的请求结果未知仍可能要求重启服务，
不能把这类错误当成明确的占用拒绝。

`/rename`、`/archive` 命令和 `/delete` 只作用于当前会话，不支持在命令后附目标 ID。要
重命名另一个普通会话，应先 `/resume`；`/sessions` 行内的“归档”和经独立红色确认卡的
“删除”是明确例外，不需要先切换，也不改变 `/archive`、`/delete` 命令的语义。

## Model、Effort、Speed、Task Feedback 与 @ 时读取的消息范围

- `/new` 卡片可以为新会话选择继承 Codex 或显式 Model、Effort 和 Speed；群聊和群话题
  还可选择 @ 时读取的消息范围；Reaction Pulse 默认关闭，Progress Card 和结束时 @ 提醒默认开启，可独立调整。
- `/config` 原子修改当前会话后续新 Turn 的三项模型设置、三个 Task Feedback，以及群聊 @ 时
  读取的消息范围。它不创建 Turn，也不能直接配置另一个会话；应先 `/resume`。
- 当前 Turn 运行、停止中或正在压缩时不能修改配置。运行时的普通消息仍只会 steer 当前 Turn。
- 已经开始的 Turn 沿用开始时捕获的 Task Feedback；之后修改只影响后续新 Turn。
- 过程卡内容、数量、长度与组织方式在 Admin 编辑。飞书 `/new`、`/config`、`/defaults`
  和定时任务表单仍只提供原有过程卡总开关，修改其他选项不会覆盖细项或改变其未配置状态。
- 选项来自 Codex 实时模型目录，并在卡片提交及每次新 Turn 前重新校验；手册不维护静态模型名单。
- 若目录需要分页而当前 SDK 无法完整读取，会明确拒绝，不静默提供不完整的模型列表。
- 没有 Netizen 会话配置时，三项显示“继承 Codex”，启动 Turn 时不显式传入三项覆盖；
  这表示配置来源，不声称已经反查到 Codex 的实际有效值。保存显式选择后，每次新 Turn
  都会重新解析并应用；当前 running Turn 仍沿用其启动配置。
- 不提供 `/model`、`/effort` 或 `/fast` 独立命令。Fast 是同一模型的 Service Tier；Codex Spark 是独立 Model。
