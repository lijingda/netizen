# 核心心智模型

[手册目录](user-guide.md) · [命令索引](commands.md)

## 界面中会出现的词

卡片和回复里会出现一些 Codex 的术语，含义如下：

| 词 | 含义 |
| --- | --- |
| 会话（卡片里有时写作 Binding） | 你在飞书里与 Codex 进行的一段对话，属于一个 Project。 |
| Codex 会话、Thread | 会话在 Codex 中的完整历史记录，也能在 Codex App/CLI 中继续。会话收到第一条真实任务时才会创建它。 |
| 一轮任务、Turn | 从你发出一条任务到 Codex 结束执行的一次运行。 |
| 补充消息、steer | 任务运行中再发的消息，会加入正在运行的这一轮，而不是排成下一轮。 |
| 原生 | 由 Codex 自己管理的能力或数据，例如历史、工具、Skills、MCP 和权限。 |
| 当前会话、当前指针 | 一个聊天位置里，普通消息默认发往的会话；Admin 筛选中叫“当前指针”。 |
| Scope | 聊天位置，即单聊、群聊主线或一个话题；出现在 Admin 筛选与删除确认中。 |
| Lazy | 尚未开始的会话：已经新建，但还没发出第一条任务，Codex 中还没有它的历史。 |
| 物理 Turn | Goal 自动推进时的每一轮；一个 Goal 由多轮组成。 |

## 聊天位置、会话与 Project

- 每个单聊、群聊主线和普通话题都是一个独立的聊天位置。一个位置可以有多个会话，但同一时刻
  只有一个当前会话；切换当前会话不会停止其他会话中正在运行的任务。
- 新建会话必须选择一个已登记且启用的 Project，使用它的默认目录，或明确选择一个受管
  worktree；Netizen 不会用服务所在目录兜底。
- `/new` 新建并切换到一个尚未开始的会话；若选择新建 worktree，会先创建 worktree。
  发出第一条真实任务时，才会在 Codex 中创建对应的会话记录。
- 配置了[聊天默认配置](sessions.md#默认会话配置与自动创建)后，没有当前会话时直接发送任务，
  机器人也会自动创建会话并执行。群聊主线和各话题共用所属聊天的默认值，但各自有独立的
  当前会话和上下文。
- 会话历史由 Codex 保存，可以在 Codex App/CLI 中继续；App/CLI 中新增的消息不会回填到飞书。
- 每条任务或补充消息都会附上当前飞书消息发送者的公开信息，并随任务一起保存在 Codex 历史中。
  它只说明请求来自谁，不授予权限、任务所有权或更高的指令优先级。机器人会从当前聊天的
  成员名单补全发送者的真实显示名；补全失败时本条消息不会执行，并提示管理员为飞书应用开通
  `im:chat.members:read` 权限、发布应用版本后重试。发送者只用当前应用内的 `open_id` 标识，
  不附带 `union_id` 或租户级 `user_id`。
- 任务正文（普通消息、Goal 目标、Side）会保留真实 @ 的名称和位置，包括触发任务的机器人
  自身；其他真人或机器人还会附带当前应用内的 Open ID，方便 Codex 区分同名对象，机器人
  自身用专门的标记表示。引用和补充的历史消息保持原样。这些标记只是信息：Codex 回复中的
  名字不会自动变成飞书 @，也不授予任何权限。
- 服务只为本进程实际打开的会话保持连接。当前会话空闲 15 分钟后会自动断开连接；切换到其他
  会话后，旧会话一旦空闲就立即尝试断开。断开连接不影响会话历史。服务重启后不会为此扫描
  历史会话或恢复旧的计时。
- 不同会话可以同时运行。使用同一个实际目录的会话共享文件和 Git 分支，Side 也使用来源会话
  的目录；不同 worktree 的文件彼此独立，但这不是权限隔离。多个会话同时修改同一个文件时，
  需要使用者自行协调。
- 谁能使用机器人，由飞书应用的可用范围和群成员身份决定；Netizen 不另设用户、群或角色白名单。
  能向机器人发送有效消息的人都可以管理所在位置的会话或当前 Side，不按会话创建者区分权限。
  所有人共用部署服务账号的 Codex 工具和文件访问能力，因此部署者应把应用限制在受信的用户和
  群范围内。Admin Web 单独通过飞书登录，并核对实例管理员名单。

## 一轮任务与补充消息

- 当前会话空闲时，普通消息开始新的一轮任务。
- 任务运行时，普通消息会补充到正在运行的这一轮，用于补充条件、纠正方向或追加要求。
- 如果补充消息恰好赶上这一轮结束，本条消息不会执行；看到提示后需要重新发送。
- Netizen 不维护消息队列，不会把运行中的新消息悄悄排成下一轮，也不会把多条消息合并成一条任务。
- 一轮任务以完成（`completed`）、中断（`interrupted`）或失败（`failed`）结束。即使失败，
  会话和历史也都保留，下一条消息可以在同一个会话开始新一轮，不必为了保留上下文而换会话。
  如果 Codex 返回了具体的中断原因，回复或过程卡会一并显示；该任务仍是中断状态。
- 如果暂时无法确认这一轮的状态，Netizen 会在几秒内做一次短暂重试。确认仍在运行，就继续正常
  跟进并接收补充消息；确认已经结束，就交付结果。仍无法确认时会显示
  `turn-observation-unavailable`：这个会话暂停自动跟进并保持占用，其他会话不受影响。可以在
  `/sessions` 中重新检查一次，也可以停止、归档或删除它；归档和删除不需要先恢复状态。已经
  确认结束后，即使读取最终回复失败，也不会再进入这种状态。
- 想开始一个独立的新任务时，等当前这一轮结束、先 `/stop`，或切换、新建另一个会话。不同会话
  可以同时运行。
