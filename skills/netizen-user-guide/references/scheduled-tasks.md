定时任务自 v0.6.0 提供，支持私聊、普通群和话题群的执行投递。已安装实例是否提供此入口，
以其 `/help` 和 Admin 页面为准。

## 创建与执行目标

可直接在群聊或私聊中创建。比如在群里说：“每天北京时间九点，在当前群总结 test 项目的进展。”也可说
“列出这个群的定时任务”“把周报改到周五下午五点”“暂停周报计划”“把周报任务现在跑一次”。省略目标 chat_id 和
Project 时使用当前普通会话；在私聊中默认投递到当前私聊，也可明确给出 chat_id 和 Project。
Netizen 不负责按会话名称搜索 ID，目标会话须能被机器人访问。自然语言管理工具由 Netizen 自动接入，不需要另外
安装 MCP 或定时任务 Skill。

执行目标有两种：每次在新话题执行，或在固定的原会话继续。比如“十分钟后在当前会话
继续检查刚才的问题”，会沿用这条会话的上下文；到点时空闲就启动新一轮，运行中就把
指令追加给当前任务。原会话目标创建后固定，后续切换会话不会把计划转投到新会话。
切走后仍可通过 `/cron`、Admin 或自然语言管理计划，旧表单也保留原目标；只有执行时
才要求目标会话当前激活，保存计划不会自动切回原会话。

## 工作区选择

新话题计划可在 Admin、`/cron` 或自然语言中选择工作区。例如：“每天九点新建一个
Worktree，检查 main 分支的测试，再把结果发到这个群。”

| 策略 | 执行时使用的目录 |
| --- | --- |
| 项目目录（默认） | 使用 Project 登记的目录。 |
| 指定已有 Worktree | 每次使用指定受管工作区的当前文件和分支，多个执行可以共享它。 |
| 每次新建 Worktree | 每个实际执行的任务新建 detached 工作区；可以指定起点 revision，留空使用创建当时 Project HEAD。 |

后两项适用于 Git 项目。新建只带已提交内容，不复制未提交改动、忽略文件或依赖，不运行
初始化脚本。保存、预览、加载选项及被跳过的执行都不创建工作区。一次执行生成的会话
之后继续使用自己的目录，不随计划编辑或下次执行而换目录。

新话题计划未指定工作区时使用项目目录，不读取聊天 `/defaults`，也不会自动沿用来源
会话的 Worktree；修改计划时没有修改工作区则保留原选择。原会话计划直接使用目标会话
的实际目录，表单只读展示，不可另外指定工作区。

指定 Worktree 不可用时，计划与原启停状态保留，列表和详情显示具体原因，“立即运行”
不可用。编辑时保留原选择，可重新选择有效工作区或改用项目目录；也可先修改名称等
其他内容。状态在打开或刷新时更新，执行前仍会重新检查。

若执行前已发现工作区被删、目录缺失/替换或状态无法确认，本次不会创建话题、会话或
启动任务，也不自动切换目录、重建替代品或补跑。已被认领的一次会在最近执行中说明
“工作区不可用，本次未执行”；立即运行在受理前被拒绝则不会新增执行记录。检查通过后
又发生删除等变化，可能已经产生话题，此时保留话题并说明已知失败。

同路径新建的工作区不是原资源，需重新选择。删除“每次新建”某次历史执行的工作区
不会使整个计划失效。已生成的工作区独立保留，在 Admin 显式管理；暂停、修改或删除
计划都不会自动回收它。

## 飞书管理卡片

`/cron` 打开管理卡片，默认当前飞书聊天已启用且未结束的任务。通过筛选下拉框选择当前飞书聊天/全部飞书聊天及启停状态并确认，
再选择任务，在原卡片查看详情、立即运行、编辑、启停、删除或展开最近执行；执行话题可通过飞书搜索定位。
卡片每批提供最多 50 个任务选项，可翻页；筛选切换会清除旧选择，编辑和启停后保留仍符合筛选的任务。
“刷新任务”只在选中任务后出现，用于重新读取该任务的信息；重新确认筛选可更新任务列表。
新建入口在管理卡底部；有当前 Agent 会话时另提供“在当前 Agent 会话中定时执行”。新建和编辑使用完整
表单，填写名称、指令、频率及对应时间；新话题模式另选 Project、工作区和 Agent 会话配置，
目标飞书聊天有“当前聊天、选择群聊、填写聊天 ID”三种方式，新建默认当前聊天，包括
当前单聊或群聊，在话题内指所属聊天。选择群聊时可输入群名关键词并点击“查找群聊”，
再从下方带头像的本页结果中选择；填写 ID 支持群或与本机器人的单聊。只有所选方式生效，
其他字段的残留值不会覆盖目标；选群或填 ID 时必须提供相应值，留空不会改用当前聊天。
编辑保留任务原目标，聊天信息读取失败也不会更换目标。多页结果可选择页码并点击“跳转”，
前后任意跳页；跳页使用本次完整查找结果，
不重新查询群目录，并保留已选群和任务草稿。修改关键词后需重新点击查找，从第一页开始
并清空旧结果选择；其他任务字段保持不变。完整结果过大或未能及时查完时，会提示细化
关键词或填写 ID，不会只给一部分群并声称查找完成。
固定 Agent 会话模式只读展示目标及所属飞书聊天/话题，沿用目标的当前配置，不另选聊天。
加载项目工作区选项和查找群聊都会保留已填写的名称、指令、时间与会话配置；某一组选项
读取失败会单独提示，不需要重新填写整个表单。已保存但不可用的工作区会保留显示。
取消返回管理卡。时间字段旁标明适用频率，均按所填时区解释；
校验失败保留填写内容，陈旧表单须刷新。私聊和群聊采用相同的创建流程。

## Admin 管理

Admin 的“定时任务”页提供相同管理能力，也可点击“立即运行”。按 Project、启停状态和结束状态筛选，
三个筛选项使用与 Sessions 一致的下拉控件，其中 Project 可搜索；定时任务每项选择一个
值，清除表示全部。选好后点击“筛选”应用，翻页或编辑计划后刷新不会应用尚未提交的筛选修改。
默认显示全部 Project 中未结束的计划，包含已暂停计划。新话题模式最后一次仍在启动、执行
或结果待确认时也保留；原会话模式在输入交接结束后即可收尾，不等待业务任务完成。
列表分别展示启停、是否结束和执行结果；已结束不表示执行成功。工作区不可用时单独说明原因，
不把已启用的计划改成已暂停；列表、详情和编辑中均可查看所选策略。
没有后续触发机会时不显示启停按钮，仍可编辑时间重新安排。
“详情／最近记录”打开只读抽屉，可查看计划与触发记录并前后翻页。加载中和查询失败会
直接显示在抽屉内，可重试；关闭后回到原列表位置，不必到列表底部寻找详情。
点击目标会话名称可以打开飞书聊天。创建/编辑在独立侧边表单中完成：Project 从列表选择，
一次性日期时间按表单中的时区填写，预览后保存；取消保留列表位置。新话题目标先选群聊
或单聊：群聊使用可搜索选择框，也可手动输入聊天 ID；单聊填写聊天 ID，推荐直接在
目标单聊使用 `/cron` 并选择“当前聊天”，无需查 ID。Admin 和卡片的 ID 输入旁均有
[如何获取聊天 ID](https://open.feishu.cn/document/server-docs/group/chat/chat-id-description)帮助：
飞书 7.60+ 可在聊天设置中查看单聊、群聊 ID。填写的是聊天 ID，不是用户 ID；单聊需是
与本机器人的聊天。提交时服务端检查目标可访问性，失败保留草稿；校验通过不保证未来
权限变化后仍可发送，任务执行时仍可能因机器人退群或权限变化失败。
原会话目标在 Sessions 中找到具体会话，点击该行“更多 → 创建定时任务”，抽屉自动锁定该会话，
沿用其 Project 与会话配置。从定时任务页选择“在原会话继续”时，点击“前往 Sessions
选择会话”；已填名称、指令和时间会暂存在当前页面，选中目标后恢复，刷新页面会丢失。
这一选择步骤不弹放弃提醒；明确取消选择或离开流程时，有修改仍需确认是否丢弃草稿。
保存后仍停留在 Sessions 原列表位置，可点击“查看定时任务”进入管理页。
也可为非当前会话建立计划，但会自动暂停至该会话恢复为当前会话，
创建计划不会自动切换或恢复目标。

## 立即运行

“立即运行”按计划当前保存的指令和执行目标触发一次；原会话模式使用目标当时的配置。
它不改变原定时安排、下次执行时间或启停状态；暂停、已结束的计划也可手动运行。
重新启用只恢复未来自动触发，不等于立即运行。回执“已受理”表示触发成功，不表示任务
完成；最近执行会标明“手动触发”或“定时触发”。新话题模式上次首轮仍在执行或状态
不明时暂不能再次运行；新话题指定工作区不可用时也不能运行。原会话模式的下一次触发独立，但目标不可用或 Project 不可用时
同样拒绝。Admin 响应未知时先查看最近记录；卡片原样重试和
自然语言工具保留同一请求凭据核查，不会重复启动。

## 会话配置与任务反馈

新话题计划支持与 `/new` 相同的模型、思考强度、速度、执行中表情闪烁、过程卡、结束时 @ 提醒和消息读取范围。
默认采用创建时当前会话的配置，可在“会话配置”中修改，也可自然语言指定，例如“使用当前
配置，但开启过程卡”。保存后与来源会话独立；修改计划只影响后续执行，某次话题的 `/config`
只修改那次会话。“自动带上期间的群聊讨论”只读取该次新话题内的增量，私聊不提供此选项。

原会话计划不保存独立配置。每次先在原位置发一条“定时任务”触发消息，接收、表情、
过程卡和异常反馈都沿用普通消息规则；开启 catch-up 时会补充上一条已接受边界到本次
触发消息之前的群聊讨论。系统输入启动的新一轮不结束 @；若只是追加当前任务，原轮的
过程卡、结果位置和结束 @ 均不变。记录“已启动新一轮”或“已追加当前任务”只表示输入
已被接受，不表示工作完成。锚点发送失败或未知时本次不执行；输入接收未知不重试，
也不额外阻塞下一次触发，但 Runtime 自身不可用时仍会像普通用户消息一样拒绝。

## 时间规则

支持一次性、每天、每周和每 N 分钟四种规则，精度为分钟。服务按整分钟检查到期计划，
固定间隔计划可能等待接近一分钟才被触发；修改计划会主动唤醒检查。
新计划默认使用服务主机解析到的 IANA 时区，保存后不随主机时区变化；无法解析时须填写，
例如 `Asia/Shanghai`。
每天/每周跟随该时区的当地时间；夏令时不存在的时刻跳过，重复时刻只执行第一次。
固定间隔从创建后的 N 分钟开始，暂停后启用保留原时间基准。当前不支持任意 cron 表达式、
每月或节假日日历。

重复计划可设置截止日期时间，默认不限，例如：“每天九点提醒我，截止到九月三十日十八点”。
`/cron` 和 Admin 的创建、编辑表单均提供可选截止时间，留空即可取消截止。
截止时刻仍允许触发；截止不会停止正在执行的任务。新话题模式等待最后一次首轮收尾，
原会话模式只等待最后一次输入交接收尾，随后计划显示已结束。

## 执行与生命周期

新话题模式每次触发都新建独立飞书话题与普通持久会话，不带入创建计划时的聊天历史，也不切换
来源私聊、群聊或话题的当前会话。应在计划指令中写清要做的工作和资源位置。结果在新话题
交付；随后继续提问、`/status`、`/stop`、配置、归档和删除都沿用普通会话能力。

- 暂停、修改或删除计划影响后续触发；已经认领的本次执行仍可能继续。删除计划保留
  已有话题、会话和工作区；在执行话题 `/stop` 只停止那次普通任务，不暂停计划。
- 原会话模式在目标切走或归档时自动暂停，切回或恢复后重新具备执行条件；手动暂停的
  计划仍保持暂停。暂停期间错过的时间不补跑，一次性任务过期就记为错过。删除目标会话
  会同时删除关联计划。“立即运行”不会自动切换或恢复目标会话。
- 新话题模式同一计划上一次首轮尚未结束时，定时触发跳过、手动触发拒绝；首轮结束后的人工交流不会阻止后续
  定时触发。状态无法确认时先阻塞该计划，可查看最近执行并使用普通会话控制处理。
- 停机期间错过的时间不补跑，执行失败不自动重试。正常运行迟到超过一分钟也记为
  错过；错过的一次性计划须改成新的未来时间才能再次启用。
- 停用 Project 时跳过新触发，已有会话可继续；删除 Project 会同时删除关联计划。
- 删除 Worktree 保留引用它的新话题计划，后续执行提示资源不可用。若同时删除关联会话，
  以那些会话为固定目标的原会话计划仍随会话删除；同名重新登记 Project 不会恢复旧计划。
- Worktree 已建好但会话或首轮失败时，资源仍保留，最近执行提供已知 ID/路径，可在 Admin
  核查或复用。创建结果未知、超时或服务重启不会自动再建一份，也不会重放任务。

定时计划与 `/goal` 的持续目标、`/status` 中的原生 plan/checklist 分开管理。
Side 的 slash 命令白名单保持不变，不提供 `/cron`；在 Side 中用自然语言创建计划时须显式
提供目标群和 Project，查询时可明确目标群或全部计划，因为临时 Side 没有普通会话的默认映射。
