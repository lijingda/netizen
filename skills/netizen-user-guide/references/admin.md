实例提供必备的 Admin Web，用于跨飞书 Scope 集中筛选和管理 Projects、普通 Sessions、
Side Topics、会话默认配置与定时计划。它与飞书共用同一个 Registry/Runtime，通过飞书
登录并核对当前应用的管理员名单；Channel 参与者或 Binding 创建者不会自动取得管理权限。
发送 `/admin` 可找回当前实例实际绑定的管理 URL 和根目录，无需先登记 Project 或创建
会话，也不会调用模型。有效的 Side 话题同样支持；关闭或过期的 Side 仍返回原有结束提示。

## 访问与登录

Admin 默认监听 `0.0.0.0`；首次未指定端口时从 `8787` 开始寻找可用端口，绑定后保存在
本实例配置中，之后不自动换号。多实例的管理端口彼此独立；不要仅凭默认端口猜测入口。
多网卡或服务器名称不明确时，部署者可在本实例 `config.yaml` 中设置 `adminWeb.accessHost`。
仅提供 loopback 地址时需在服务器本机访问或自行建立隧道。`/admin` 不返回登录凭据、
session token 或免登录链接，也不改变管理权限。打开管理页后点击飞书登录，在官方页面
完成确认，再回原页继续。不要在聊天中发送 App Secret 或用户 token。Admin 使用受信内网
HTTP，名单中的管理员权限相同，不提供 TLS、角色分级或 Project ACL；不应直接暴露到
不受信网络。普通使用者继续使用 `/settings`、`/defaults` 和当前 Scope 的会话命令。

## 管理员与登录状态

首位管理员由部署者在本机 setup 中授权确认，或通过 `--admin-open-id` 指定当前应用下的
用户 Open ID。已有管理员可在“系统管理 → 权限管理 → 管理员”中使用飞书选人组件添加
成员，或确认删除；可以删除自己，但不能删除最后一人。名单展示姓名、头像的本地快照，
手填 ID 尚无资料时显示 ID；展示信息陈旧不会改变权限。删除会立即撤销该用户所有管理
登录和未使用的操作授权，已经受理的任务继续运行。重新添加不会恢复旧登录。

本地登录状态不会因闲置或使用时长自动过期。退出登录、服务重启或浏览器清除会话
Cookie 后需重新登录；服务器保存飞书凭证不等于浏览器自动恢复登录。实际调用飞书时
会按需续期，续期失败需要重新登录。普通退出只结束当前浏览器登录，不清除共享用户
凭证。登录会话数量达到上限时，新登录会替换最早会话，优先替换已满来源的会话。

登录授权有有效期，取消、过期或失败时按页面提示重新开始；保留原页直到授权结果返回。
已有飞书登录态可能减少扫码步骤，但不保证跳过授权确认。新登录统一申请选人和按需
续期所需的 `component:selector`、`offline_access`；不在进入管理员页面时另行补授权。
连续失败触发限速时按提示等待后重试。管理操作凭据仍有十分钟有效期，操作页面过期时
需要刷新。旧共享密钥登录已移除，飞书登录失败不会回退到旧方式。

## 页面导航与表单

各模块有独立地址：Projects 为 `/projects`，普通／临时会话为 `/sessions/ordinary`、
`/sessions/temporary`，定时任务为 `/schedules`，默认会话配置为 `/defaults`，系统维护为
`/maintenance`，系统管理为 `/system`。已应用的筛选、排序和每页数量保存在地址的 `?`
查询参数中，未点击“筛选”的修改不会写入。例如
`/sessions/ordinary?project=netizen&sortBy=createdAt&sortDirection=asc`。
可以收藏或复制地址；浏览器前进／后退和整页刷新会恢复对应查询条件，重新读取第一页，
不恢复旧列表快照、翻页游标或未保存表单。未登录时先完成登录，再回到原管理地址；
只允许返回本实例的管理页面。旧的 `/?binding_id=...` 会话链接仍可使用。

会话配置、默认会话配置和定时任务的编辑抽屉，有未保存修改时关闭、取消、按 Esc 或
离开编辑界面会询问是否放弃；选择取消可继续填写。改回原值、仅打开查看或保存成功后
不提醒。有修改时刷新或离开整个页面会请求浏览器原生提醒，但不会自动保存草稿。

## 普通与临时会话

Admin Web 只管理已有会话，不提供新建会话入口。请在目标飞书聊天或话题中通过 `/new`
或可用的聊天默认配置创建会话；定时任务仍按保存的计划执行。
它可以管理 inactive/cross-Scope exact Binding，包括设为当前、修改
完整会话配置、重命名、归档、恢复或恢复并设为当前、删除 Lazy、Stop 和 Release，也可
在 Delete capability 可用时删除 active 或 archived 的原生 Thread。两类删除都需二次确认；
materialized 删除的确认文案会显示会话、Scope、short ID，并说明原生 Thread、spawned
descendants、Codex App/CLI 历史与本地 Binding 都会永久消失。它不能发送即时 Prompt、查看完整
历史、启动/推进 Goal、Compact、删除 Side 墓碑或执行任意选择的批量 native mutation。Admin 可查看 @ 时读取的消息
范围；但不能在没有 exact 飞书消息边界时新启用 catch-up，也不能把 catch-up 会话从后台
直接设为 current。页面操作结果未知时应刷新对账，
不要重放；服务重启或 credential 轮换会注销原 session。

Sessions 分为“普通会话”和“临时会话”两个二级 Tab，默认进入普通会话，切换时分别保留
各自的筛选、排序与分页。
筛选或翻页成功后，列表和分页一起更新；查询失败时继续显示上一次成功结果，不丢失
正在编辑的筛选草稿。
普通会话行按当前可用操作直接展示“配置”“停止”“设为当前”及恢复入口；“创建定时任务”、
重命名、归档、删除和释放订阅在“更多”中。原有危险操作的二次确认保持不变。

普通会话的“配置”打开完整会话设置表单，可修改 Model、Effort、Speed、执行中表情反馈、
进度卡片和结束时 @ 提醒；群聊及群话题还显示消息上下文设置。已有“补齐未读上下文”
可以保留或关闭，新开启仍需在目标飞书会话发送 `/config`。模型目录暂不可用时，已有
选择保持不变，仍可调整反馈或显式改为“继承 Codex”。配置只影响之后的任务；正在运行、
停止、执行 Goal 或压缩上下文的会话暂不能保存。表单失效或保存失败时，重新打开后操作。

Sessions 页的 Project、Scope、会话状态和当前指针均支持多选；同一项取“或”，不同项
取“且”。默认显示 Active、Lazy 和“状态未确认”；Project 可搜索并包含停用项目。
“状态未确认”表示暂时无法确认原生会话的归档状态，不代表会话已经删除；可稍后刷新。
目录读取失败时列表保留本地会话并提示状态不可用。“重置”恢复默认筛选、全部创建时间、
最近更新由近及远和每页数量。普通列表展示短 ID，完整的聊天、话题、Binding 和 Thread ID
在“会话标识”中展开，点击标识后可按 Ctrl/Cmd+C 复制，供排查使用。
“群聊”筛选可输入群名搜索并选择，按精确聊天 ID 筛选该群主线和话题中的会话；清空后
不限制聊天。选择框只包含机器人当前已加入且可访问的群，不提供历史群名目录。
Admin 各处的群选择框收起时显示头像和群名，点击后在弹层中搜索并查看完整群名和 ID；
头像不可用时显示通用群图标，不影响选择。输入关键词只搜索候选，未选中就关闭会保留
原选择。筛选未选群时显示“全部”，也可选择“全部”或清除已选群，再点击“筛选”应用；
创建和配置表单未选群时显示“请选择群聊”。锁定的已有目标可悬停查看完整群名和 ID。
打开配置抽屉不会自动展开群列表；点击选择框或按方向键才展开。各页单选框使用统一菜单，
选项较多时支持菜单内搜索；Escape 只关闭当前菜单，不直接关闭编辑抽屉。
未设置群筛选时，机器人退出群后的已有会话仍保留在原列表中。
每页可选 10、20、50 或 100 条；列表区分会话的消息/话题位置、当前指针和运行状态，
点击位置名称时，话题会话直接打开对应飞书话题的根消息；普通单聊和群聊主线打开所在聊天。
管理列表的聊天名称使用内存缓存：单聊名称成功解析后最多保留 7 天，群名最多保留
30 分钟，因此改名后可能延迟更新；服务重启或缓存淘汰也会触发重新查询。查询失败时
显示聊天 ID，失败结果保留 30 秒后可随下次刷新重查，不影响会话绑定。
两类会话均显示“创建时间”和“最近更新”，默认按最近更新由近及远。点击任一时间表头
切换排序字段，再次点击切换由近及远/由远及近；排序针对全部符合已应用筛选的会话，
排完后才分页，切换排序回到第一页，不提交尚未应用的筛选草稿。相同时间按 ID 固定顺序。
普通会话创建时间为本地会话记录的创建时间，“最近更新”为原生会话的最近更新时间，
均按浏览器本地时区显示。Lazy 显示“尚未开始”，原生索引更新时间暂不可用时显示 `—`；
缺失更新时间的记录在两种方向均排最后，不用创建时间冒充更新时间。
列表不是固定快照，会话变化可能改变分页位置；目录失败或恢复后建议回第一页重新查询。
“临时会话”集中展示 Side，支持项目、群聊、状态和创建时间筛选，默认显示创建中和存活的
临时会话；已结束、已失效和失败记录可通过状态筛选查看。每页同样可选 10、20、50 或
100 条，默认 20。“重置”恢复临时会话自己的默认筛选，不改变普通会话的条件。
列表显示飞书位置、来源会话、会话状态、运行态、项目、创建时间和最近更新；原始 ID 在折叠详情中。
临时会话的最近更新来自其自身记录，接受输入、任务结束或生命周期变化时更新，不是来源
会话的更新时间，也不随逐字输出变化。
点击位置打开对应话题，来源会话仍存在时可查看对应普通会话；来源已删除不会隐藏仍存活的
Side。正在关闭时仍显示结束中，已结束或失效且没有运行任务的记录显示 `—`。
可用按钮随会话情况变化：“停止”与 Side 中的 `/stop` 相同，只中断当前任务，临时会话
仍可继续；“结束临时会话”与 `/side close` 相同，结束后不能恢复。旧页面的停止操作
不会改为停止后来启动的任务，提示状态变化时应刷新。临时会话不提供归档、恢复或删除墓碑。

已确认归档且没有待核查运行活动的会话，运行态显示 `—`（已归档，不查询运行态），
这不表示历史 Goal 不存在。普通和临时会话列表均不再常驻自动刷新，页面显示最后成功
刷新时间；需要最新状态时点击“刷新”。进入页面、切换 Tab、筛选、排序、翻页和操作后的
刷新仍保留，其他页面、登录及系统维护的轮询不受影响。查询失败保留上次结果与时间，
不会自动重试。旧操作按钮仍会校验当前真实状态，状态变化时应刷新后再操作。

## Project 统计与删除

Projects 页的归档统计在状态不完整时显示“已确认”数量及另有多少会话待确认；读取失败
时显示“未确认”，本地项目和会话总数仍可查看。
Projects、定时计划及最近触发记录均提供“上一页／第 N 页／下一页”。分页不显示精确
总数，不支持任意跳页；翻页失败保留当前页，可重试。
Projects 页可“删除 Project 及关联 Sessions”。确认范围包含该项目的全部关联会话
（含归档会话）、仍需关闭的 Side、定时计划和仍在创建会话的定时执行，不受 Sessions
筛选影响；磁盘代码目录保留。提交后关联计划即删除，部分删除失败或同名 Project
重新登记都不会恢复这些计划。
全部成功后项目才从列表移除。部分失败、结果未知或 Side 尚在创建时，项目保持停用并
展示剩余项；已成功删除的会话不会恢复。后续操作须刷新清单并重新确认，不会自动续删。

## Admin 系统维护

“系统维护”显示当前 Python 安装、当前实例诊断与最近重启结果，只提供本实例“重启服务”，不再从
管理页升级共享程序。程序升级由部署者在独立终端执行 `netizen update`，不能从将被
停止的 Netizen 服务里执行。

实例诊断与 `netizen doctor --root` 使用相同的只读服务检查，展示注册、加载、运行、
就绪和自启动状态，环境详情可展开查看。进入页面或点击“刷新维护状态”时检查，不自动
轮询诊断；检查失败显示“无法确认”，上次成功检查时间不冒充本次结果。此检查不包含
飞书权限、模型连通性或数据库完整性。旧升级的已结束结果不再显示为当前告警；历史
维护未完成或结果未知时仍提示核查，不自动清除记录。

重启使用此实例已经绑定的 Python 环境中的当前程序，重新加载账号持久 shell profile，
并执行启动数据检查与必要迁移；它不安装包、不切换 Python 环境，也不保证所有原生
配置作用于已有 Thread。提交前确认停机影响：不等待任务空闲，会中断普通任务、
暂停 Goal、结束临时 Side，之后不会自动续跑。重启失败不自动回滚用户配置或已迁移数据库。

关闭页面、断线或等待超时不取消操作；响应丢失先刷新对账，不要重复点击。重启后需要
重新登录查看同一操作的结果；页面连通不等于操作成功。“服务已恢复”只表示恢复证据
得到确认，不改判原失败操作。结果未知时按提示检查实例状态与日志，不手改维护记录
伪造成功。服务已经停止时管理页不可用，由部署者使用：

```bash
netizen status --root /absolute/path/to/.netizen
netizen logs --root /absolute/path/to/.netizen
netizen restart --root /absolute/path/to/.netizen
```

这些是宿主机 CLI 命令，不是飞书 slash 命令。`--root` 选择一个实例；未指定时采用
NETIZEN_ROOT，再缺省为有效账号的 ~/.netizen。`netizen update` 更新调用它的 Python
环境及其关联实例，拒绝 --root，不是仅更新当前聊天中的机器人。
升级日志逐行显示阶段和每个实例的停止／恢复结果；包验证成功与实例 ready 分开报告。
`netizen update --json` 将最终结构化结果写入 stdout，进度和包管理器输出写入 stderr。

需要查实例清单时，在宿主机执行 `netizen doctor --json`：不传 `--root` 会忽略
NETIZEN_ROOT，列出当前用户全部可识别的受管实例，包含其他 Python 环境和已停止实例。
结果中的 `cli` 表示本次命令的 Python 环境，`count` 是实例数，`instances` 是实例数组；
每项的 `current_environment` 表示是否属于当前 CLI 环境。它不枚举其他用户或手工前台
进程，也不代表升级预检已通过。只查一个实例时用 `netizen doctor --root /path/to/.netizen --json`。

另一个 Python 环境 B 可以按 root 控制绑定 A 的实例，但 start/restart 仍运行 A，
B 的 update 不涉及 A。切换环境必须先 remove 保留数据、解除绑定，再从 B start；
不要加 --purge。remove 默认保留实例数据；--purge 才清理展示的有限实例文件，
-y 只省去交互确认，不能绕过安全检查。实例移除不卸载共享程序，也不删除 Project、
用户 Skills 或共享 Codex 历史；程序卸载交给原包管理器，先处理其关联实例。
