## `/fork` 持久分支

当前普通会话已有历史且空闲时，发送 `/fork` 打开创建卡。目标飞书聊天有“当前聊天、
选择群聊、填写聊天 ID”三种方式，默认在当前单聊或群聊中新建话题；在话题中使用时
“当前聊天”指所属聊天，不接入原话题。选择群聊时填写群名关键词并点击“查找群聊”，
从下方带头像的结果下拉框选群；填写 ID 可指定机器人可访问的群或单聊。
只有选中的指定方式生效，其他字段的内容不影响目标；选群或填 ID 时必须提供相应值，
留空不会改用当前聊天。ID 输入旁提供官方获取指南。
名称和位置在同一张表单填写，点击“创建分支”即可，无需逐页继续或确认。
“分支位置”默认当前聊天；下方群聊和 ID 输入始终展开，并以浅色背景归组。
当前聊天无需填写；选择其他方式后填写对应项即可，切换方式无需等待卡片刷新。
多页结果在选择框下方选页并点击“跳转”，可前后任意跳页，保留已填名称及所选目标，
不重新查询群目录。修改关键词后需重新点击查找，从第一页开始并清空旧结果选择；
下拉框自带的过滤只作用于本页，不代替查找。完整结果过大、查询超时或失败时可缩小
关键词重试或填写 ID，不会展示不完整结果。它不接入已有话题，
也不切换来源位置的当前会话；跨聊天会把来源讨论的上下文带到目标聊天，请确认目标后提交。
群候选会尽力显示群头像；头像加载失败时使用通用图标，仍可正常创建分支。

分支继承创建时的 Codex 历史、同一项目目录和会话设置，之后作为独立普通会话继续：
可以更改设置、使用 Goal、重启后恢复、归档或删除，来源后续设置不影响它。项目文件仍
共享，双方修改会相互可见。它不会接手来源正在运行的任务或 Goal；请等来源空闲再创建。
与 Side 不同，持久分支不会因空闲两小时或服务重启而过期。

新话题只发布一张根卡片，先显示“创建中”，完成后主标题变为分支名称，副标题显示
“会话分支已创建”，可以直接在本话题继续。只有来源会话的回执保留“进入新话题”按钮。
话题内若有辅助说明消息，它会提示查看顶部卡片的创建结果，不代表仍在创建。
**请等待创建完成后再发送消息。** 提前输入可能按目标聊天的默认配置另建普通会话并执行，
使本次分支创建因目标已占用而失败；系统不会覆盖已建立的会话。创建本身不提交模型任务。
新分支的“@ 时读取的消息范围”从新话题开始，不额外补录来源聊天的飞书讨论。
单聊分支固定只读取当前消息，不启用群聊 catch-up，但已继承的 Agent 历史仍然保留。
目标校验失败会保留表单，不创建分支；校验通过后若创建结果未知，仍按下述失败边界处理。

创建失败或结果未知时，查看卡片说明的已知结果，不要连续提交。已经创建成功的会话会
保留；中断可能留下未绑定的原生分支或话题，需要部署者按提示核查，不会自动重复创建。
删除来源或分支时遵守同一套[原生删除规则](sessions.md#归档恢复和删除)。

## Side 临时话题

Side 适合在不打断 Parent 会话的情况下讨论一个临时分支。

- `/side [首轮问题]` 要求当前会话已经有原生历史。它从当前 Parent Thread 创建临时 fork，并在同一聊天中新建一个 sibling 话题。
- 省略问题时只创建 Side；携带问题时，首轮问题和后续回复只出现在新话题。
- 携带问题时，Codex 看到的首轮来源仍是原 `/side` 消息及其发送者；新话题中的问题副本
  只承载 reaction 和最终回复。后续每条 Side Prompt 使用其实际发送者。
- Parent 和多个 Side 可以并发，但共享同一个真实 Project 目录。
- Side 在同一个临时 fork 上支持多轮：空闲时开始新 Turn，运行中继续 steer。
- Side 创建时冻结 Parent 当时的 Model、Effort、Speed、Reaction Pulse、Progress Card 与结束时 @ 提醒；
  Parent 后续 `/config` 不影响既有 Side。每轮 Side Turn 的表情、进度卡、富文本和文件卡
  与普通 Turn 使用同一规则。
- Side 内只支持普通 prompt、`//`、`/status`、`/usage`（能力可用时）、`/stop`、`/admin`、`/help`、`/` 和 `/side close`。
- Side 内不支持 Goal；需要 Goal 时回到普通会话。
- `/stop` 只中断当前 Side Turn，Side 仍可继续；`/side close` 才真正结束 Side 并取消订阅。
- Side 空闲两小时或 Netizen 服务重启后过期。旧 Side 话题不会自动变成普通会话。

Side 根卡显示来源会话、项目、发起人和本地创建时间；信息暂不可用时不会影响对话。
“查看来源话题/聊天”只打开原位置，不会自动切换当前会话。“会话详情”默认收起，点击
在卡片内展开原会话/Side 编号和项目工作目录；需要选择原会话时，可回到来源位置发送
其中的 `/resume <编号>`。原会话已删除时不显示恢复命令。结束或过期后，历史消息仍可查看。

若 Side 显示创建或关闭结果不确定，应在原 Side 话题按提示重试 `/side close`，不要把它当普通话题使用。

## Goal

Goal 适合让 Codex 围绕一个持续目标自动推进多个物理 Turn。

- `/goal`：发送当前会话的 Goal 管理卡。它是静态快照，点击刷新或再次输入 `/goal` 查看最新状态。
- `/goal <目标>`：启动一个 Goal。
- `/goal pause`：暂停后续自动推进，当前任务继续执行；`/goal clear` 清除目标，同样不停止当前任务。
- `/goal resume`：恢复目标。当前任务仍运行时继续沿用原回复，之前执行已结束时开始新的回复。
  管理卡提供同样的操作，点击时会重新核对当前目标。
- 任务答案与 Goal 管理卡分开展示。开启 Progress Card 时，同次连续执行更新同一张回复卡；
  关闭时按普通任务使用富文本，产生文件时展示文件卡。阶段性答案跨自动换轮保留，
  新一次连续执行重新开始。任务清单是最近一次原生上报，可能尚未反映追加消息。
- Goal 确认完成且最终任务成功结束后自动清除；暂停、受阻、额度限制或收尾不确定时不会
  自动清除。收尾结果未知时不自动重试，但已确认的最终回答仍会显示；管理卡不保存旧答案。
- Goal 运行期间，可以继续发送普通消息（也可引用消息、附图片或使用 `$skill`），
  补充到当前物理 Turn；准备期间恰好换轮会明确提示重发，不会自动改投下一轮。
  启动、正在停止、收尾或状态未知时不接收；只暂停或清除目标后，仍在执行的当前任务
  继续接收补充消息。执行期间同一会话仍不能使用 `/compact` 或 `/config`。
- 可以发送“暂停一下”让模型理解并处理；只暂停目标使用 `/goal pause`，立即停止当前执行使用 `/stop`。
- `/stop` 会先暂停 Goal，再中断当前物理 Turn；它不会把 Goal 当普通一次性任务清除。
- 当前不支持在 Goal objective 中调用 `$skill`；请先在普通消息中使用 Skill。

当前 SDK 对原生 hook 导致的自动中断后续跑存在观察缺口。若提示 Goal 终态未确认，
原生任务可能仍在运行；Netizen 只保留当前 Goal 的占用，不影响其他会话，也不会把旧
轮次当作最终结果。稍后发送消息或查看 `/goal` 会重新检查：确认 Goal 已停止自动执行、
原生会话空闲后，可直接在同一会话继续对话，无须重启服务。若仍在运行或无法确认，
本次输入会明确拒绝，请稍后重试，或先在原生 Codex 核查并暂停 Goal。

Goal 和 Side 都依赖运行时原生能力门禁。如果当前 `/help` 没有显示相应命令，以当前实例能力为准。
