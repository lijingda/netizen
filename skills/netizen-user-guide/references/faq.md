## “我又发了一条消息，为什么没有新开任务？”

如果普通 Turn 或 Goal 的当前物理 Turn 仍在运行，新消息会 steer 它；若恰好撞上完成或
换轮，本条消息未执行并提示重发。启动、停止、收尾或压缩状态会拒绝普通消息。
等待状态回到空闲、先 `/stop`，或 `/new`、
`/resume` 到另一个会话，才能开始独立 Turn。

详见[Turn 与 steer](concepts.md#turnsteer-与排队)。

## “群里机器人为什么没响应？”

群主线和群话题的每条触发消息都必须重新 `@机器人`；未 @ 的消息不会触发响应。若当前
会话选择“自动带上期间的群聊讨论”，这些消息可能在下一次 @ 时作为背景进入 Codex，但
仍不会自己触发 Turn。还应确认机器人仍在群内，且飞书应用的可用范围和消息权限已发布。

详见[快速开始](user-guide.md#快速开始)与[群聊消息范围](messages.md#群聊的--时读取的消息范围)。

## “为什么不能修改配置？”

当前会话可能正在运行、停止或压缩。等待其回到空闲后再用 `/config`；要配置别的会话，先 `/resume`。

详见[会话设置](sessions.md#session-settings)。

## “为什么没有执行中表情闪烁或进度卡？”

新建会话的 Progress Card 默认开启，Reaction Pulse 默认关闭；已有会话保留原设置。
可在 `/new` 卡片中选择，或等当前会话空闲后通过 `/config` 修改；两项互不依赖。
即使 Reaction Pulse 关闭，任务
accepted、成功 steer 和终态仍会尽力显示生命周期表情。Progress Card 关闭并不影响普通 Turn 的
最终回复：没有文件时仍回复富文本/静态文本，有文件时仍使用完成卡。Goal 的任务回复
也遵循这一设置；`/goal` 的静态管理卡独立展示。Side 使用创建瞬间冻结的 Parent 选项；
若想改变既有 Side 的反馈方式，需要回到 Parent 修改后重新创建 Side。

详见[运行反馈](feedback-and-files.md#飞书中的运行反馈)与[Side 设置](fork-side-goal.md#side-临时话题)。

## “为什么 `/delete` 删除不了？”

已有原生历史的会话必须已持久化且当前实例的 Delete compatibility gate 可用。普通 Turn、
Goal、Compaction 或 Turn 观测不可用时也会直接委托 App Server removal，不要求 Netizen 先确认
终态。ephemeral、未持久化、compatibility gate 不可用或 App Server/存储故障仍会拒绝。失败提示
若有明确原生拒绝，请先处理提示中的原因，再发送 `/delete` 并再次确认；若说结果 unknown，
目标会话会保持占用且不应连续点击，应由部署者核查。分支仍引用来源历史也可能阻止删除
来源，需要先处理该分支。请求未知或原生已不存在仍可能留下本地关联，不会自动清除；
其他会话仍可继续使用。只想隐藏并保留历史时使用 `/archive`。

详见[归档、恢复和删除](sessions.md#归档恢复和删除)。

## “Turn 失败后还要换会话吗？”

不用。`failed` 只结束本轮 Turn，原 Thread、历史和 Binding 都保留；回复会显示可用的错误
原因和错误码。可修正问题、调整配置或稍后发送“继续”，在同一 Thread 开始新 Turn；
不会自动重跑旧任务或撤销已执行的操作。如果显示 `turn-observation-unavailable`，说明仍无法
确认 exact Turn，自动周期读取、Reaction Pulse 和进度卡轮询已停止，原消息上已记录的
`Typing`/`THINKING` 也会尽力清理，但不会冒充任务已经结束；后续若确认终态仍会收到普通
完成回复。新消息会先触发一次有界状态检查：确认上一轮结束后才开始新一轮；若上一轮仍
运行，则将本条消息补充到原任务；仍无法确认时本条消息不会执行，并返回最近的具体原因。
也可从 `/sessions` 重新检查，确认之前失败后会补发原因并解除本轮占用。
检查期间若又停止或切换了会话，等待中的旧消息不会随后执行，需要重新发送。
若先前停止尚未完成，恢复状态读取也不会撤销停止；请等待结束，或按提示重试 `/stop`。
停止确认完成后，可以正常发送新消息开始下一轮。旧进度卡不会恢复更新，新一轮使用正常反馈。
检查不是重新执行任务。停止、归档或删除仍可从 `/sessions` 操作；归档/删除不需要先修好观测，其他
会话不受影响。

详见[Turn 状态与恢复](concepts.md#turnsteer-与排队)与[会话管理](sessions.md)。

## “`/stop` 已完成，为什么进程还在？”

`/stop` 能确认原生 Turn 已中断，并请求清理已登记的后台 terminal，但不能证明前台工具进程已经退出。这是当前原生接口限制。

详见[停止任务](status-and-control.md#stop)。

## “CLI 能找到一个工具，为什么飞书里提示找不到？”

先确认工具路径或变量已经写入服务账号的持久 shell profile，而不是只在当前终端临时
`export`。Netizen 会在每次服务启动时重新读取 interactive login shell 的导出环境；修改
profile 后需要由部署者执行 `netizen restart --root "<NETIZEN_ROOT>"`，指定目标实例。
alias、未导出的 shell function 和依赖
真实 TTY 的初始化不属于后台服务可继承的环境。Bash 用户若只在 `.bashrc` 配置 NVM，需
确认 `.bash_profile` 或 `.profile` 会 source 它。

详见[宿主环境差异](native-capabilities.md#与-codex-appcli-的差异)与[实例维护](admin.md#admin-系统维护)。

## “Side 为什么不能继续了？”

Side 可能因空闲两小时、服务重启或关闭流程进入终态而过期。旧 Side 话题不会恢复为普通会话；回到 Parent 后重新 `/side`。

详见[Side 生命周期](fork-side-goal.md#side-临时话题)。

## “引用或图片失败后会不会只发送文字部分？”

不会。引用或图片准备采用整条消息准入；任一必需资源失败时零 start/steer。修复权限、缩小图片或重新选择内容后，由用户重发。

详见[消息、引用与图片](messages.md)。

## “为什么任务生成了文件，却没有出现‘本轮文件’？”

当前版本从成功修改、生成图片及可用的原生 diff 发现文件，并补充可确认归属的本轮
新建子任务记录。Goal 只取最后一轮，Side 不读取 aggregate diff；两者都不聚合更早
轮次。子任务读取有界，运行中或读取不到的文件不保证补齐。三者都不解析最终回复中的
路径，也不扫描 Project。shell、MCP 或第三方工具生成但未进入这些原生记录的文件，
以及压缩输出，都不会进入卡片。文件必须仍存在且是普通文件；
Project 不是额外的文件权限边界，本轮明确报告的其他目录文件仍可出现。

详见[本轮文件的来源与展示](feedback-and-files.md#查看和发送本轮文件)。

## “点击本轮文件后，拿到的是任务完成时的版本吗？”

不保证。本轮文件不保存快照、摘要或修改检测；点击时发送卡片所记路径当前仍可访问的
内容。若其他会话已经修改、替换或重绑文件，发送的是当前版本；若文件已消失或变成
非普通文件，则拒绝发送并保留原卡片。

详见[本轮文件的发送规则](feedback-and-files.md#查看和发送本轮文件)。
